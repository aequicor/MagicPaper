# Движки сессий

В «Новой сессии» выбирается **pi** или **Codex**. Выбор сохраняется в `CodingSession.engine` и больше не меняется. Модель и её подключение можно менять между запросами. Параметр в «Настройки → Движки» задаёт только первоначальный выбор для новых сессий.

| Подключение | pi | Codex |
| --- | --- | --- |
| OpenAI, подписка ChatGPT | Нативный транспорт pi `openai-codex-responses` | Нативный Codex app-server |
| OpenAI-совместимые API и локальные серверы | Нативный транспорт pi | Адаптер Responses → Chat Completions |
| OpenRouter | Нативный транспорт pi | Адаптер Responses → OpenRouter |
| Anthropic | Нативный транспорт pi | Адаптер Responses → Messages |
| Google | Нативный транспорт pi | Адаптер Responses → Gemini |

Во всех случаях агентские инструменты, разрешения и выполнение принадлежат выбранному движку. Библиотека pi-ai в адаптере Codex используется только для обращения к API; второй pi-агент не запускается. Codex сохраняет свою песочницу и механизм подтверждений. Эти свойства не переносятся на pi.

## Подготовка и вход

Состояние, подготовка и удаление зависимостей перенесены с экрана проектов в «Настройки → Движки». Там же находятся общий вход ChatGPT и выбор движка новых сессий. Подключения моделей остаются в разделе «Модели».

Для pi с подпиской нужен установленный Codex: он управляет входом и обновлением токенов в отдельном профиле MagicPaper. pi получает только актуальный access token перед каждым обращением к модели, через временный локальный канал с отдельным случайным ключом. Refresh token не копируется. Ключ этого канала удаляется из окружения до запуска инструментов pi. Учётные данные пользователя в обычных Codex/ChatGPT-профилях не изменяются.

Для сторонних API в Codex используется библиотека из зависимостей pi. Кнопка «Проверить и подготовить» проверяет Codex и подготавливает эту библиотеку. Удаление зависимостей запрещено во время активных сессий. Установкой самого Codex управляет его установщик; MagicPaper ищет установленный исполняемый файл, также поддерживается `MAGICPAPER_CODEX_PATH`.

## История и планирование

Сессии старого формата получают движок однократно по прежнему правилу выбора подключения: подписка → Codex, API → pi. Репозиторий сохраняет результат миграции и отвергает последующие попытки заменить движок. Идентификатор контекста и сообщения остаются прежними.

Новый план сохраняет движок родительской сессии; мастер создания отдельного плана тоже предлагает выбор. Исполнители, объединение изменений и итоговая проверка наследуют этот движок. Каждая попытка хранит его отдельно, поэтому восстановление работы не зависит от изменившихся общих настроек.

Для каждого запроса Codex открывается отдельное соединение app-server, а сохранённый диалог продолжается через `thread/resume`. Это необходимо, поскольку уже загруженный в app-server диалог может игнорировать изменения конфигурации провайдера. Соединения параллельных сессий независимы.

Адаптер поддерживает потоковый текст, группы инструментов, обычные и свободноформатные вызовы инструментов, результаты вызовов, приложенные изображения, параметры генерации и сжатые запросы. Неподдерживаемый формат и обрезанный ответ выдаются как ошибка. Переключения на другой движок при ошибке нет.

## Проверка

Основная проверка: `./gradlew :shared:jvmTest :desktopApp:compileKotlin :shared:compileKotlinJs :shared:compileKotlinWasmJs`.

Локальные проверки JavaScript находятся в `shared/src/jvmTest/resources/coding/`:

- `node --test shared/src/jvmTest/resources/coding/provider-bridge.test.mjs` — протокол, авторизация канала, инструменты и ошибки.
- `codex-provider-integration.mjs` — настоящий Codex, тестовая модель, исполнение команды и продолжение истории после обновления подключения.
- `pi-subscription-integration.mjs` — настоящий pi, нативный транспорт подписки, искусственный токен, чтение файла и получение свежего токена перед следующим запросом.
- `other-providers-integration.mjs` — форматы Anthropic, Google и OpenRouter, инструменты и параметры генерации.

Интеграционным сценариям нужны `MAGICPAPER_PI_AI` (file URL каталога `pi-ai/dist/` с завершающим `/`), `MAGICPAPER_PI_CLI` (путь к pi CLI) и для проверки Codex — `MAGICPAPER_CODEX_PATH`. Они запускаются через Node после подготовки зависимостей. Все серверы моделей локальные, аккаунты и оплачиваемые запросы не используются. Реальный вход ChatGPT и запросы к внешним провайдерам в этой проверке не выполнялись.

Снимки интерфейса: `shared/build/reports/engines/`.
