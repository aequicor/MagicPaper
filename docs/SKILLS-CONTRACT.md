# Контракт пакетов, версий и доверия навыков v1

Этап «Формат, версии и доверие», 2026-09-07.
Основание: [обследование](SKILLS-DISCOVERY.md), согласование D1–D5
`mtrb1n8g-f8c7a893` и заменяющее прежние ограничения сообщение планировщика
`mtrahjwx-96b63428-turn-2-action-0`.

Реализованы сериализуемый общий контракт, структурная проверка и проверка
графа в commonMain, эталонный JVM-валидатор байтов/каталога/локального staging
и атомарная машина состояний в памяти. Это граница следующей реализации:
сетевые загрузчики, распаковка ZIP, Git, постоянное хранилище, UI согласия и
подключение к агенту в данном этапе не реализуются. Старые Skill/CatalogEntry,
SkillInstaller и импорт профиля ещё используют прежнюю модель; они не должны
служить входом для внешних пакетов до интеграции нового контракта.

## Формат

Исходник: [SkillPackage.kt](../shared/src/commonMain/kotlin/io/aequicor/magicpaper/domain/SkillPackage.kt).
Пакет — `skill-package.json` (UTF-8 JSON) и перечисленные в нём обычные файлы.
Никаких действий установки, hooks, автозапуска или загрузки зависимостей при
чтении пакета. Все ресурсы — данные, включая файлы с расширениями скриптов.

| Поле | Контракт v1 |
| --- | --- |
| schemaVersion | Ровно 1. Неизвестные поля/значения enum отвергаются JSON-декодером. |
| id | Стабильное имя до 128 символов, `[a-z0-9]+([.-][a-z0-9]+)*`. Не название UI и не доказательство принадлежности издателю. |
| version | Стабильная тройка `major.minor.patch`, компоненты 0..Int.MAX_VALUE, без ведущих нулей, prerelease/build-суффиксов. Это намеренно ограниченное подмножество SemVer. |
| name, description | Непустые отображаемое имя и описание условий применения. |
| instructions | Путь к непустому UTF-8 файлу инструкции; по умолчанию SKILL.md. |
| files | Полный список инструкции и ресурсов: path, размер в байтах, SHA-256 в 64 строчных hex-символах. Манифест в список не включается. |
| dependencies | Уникальные id и точные version. Нет latest, диапазонов, необязательных зависимостей или автоматического разрешения через сеть. |
| permissions | READ_PROJECT, WRITE_PROJECT, NETWORK, RUN_PROCESS. Отсутствие означает пустой набор. Новое неизвестное разрешение требует новой схемы. |
| origin | kind: LOCAL_DIRECTORY, ZIP, GIT или HTTPS_PACKAGE; необязательные location, publisher, revision. Это заявления автора, не результат проверки. |
| license | Идентификатор/выражение SPDX либо ссылка вида LicenseRef на лицензию в ресурсах; null означает неизвестную лицензию. Строка не проверяется по внешнему SPDX-реестру и не даёт доверия автоматически. |
| compatibility | minHost включительно, maxHostExclusive исключительно; обе версии в формате выше; platforms — список идентификаторов платформ, например desktop/android/js/wasm. Проверяющий передаёт актуальные версию контракта хоста и платформу явно. |

Версия протокола хоста — не версия LLM. На этапе интеграции приложение должно
назначить свою версию поддержки навыков; тестовый хост `1.0.0/desktop` не
объявляет поддержку новых пакетов уже существующим runtime.

Общий каталог `SkillPackageCatalog` содержит schemaVersion=1 и releases.
Каждая запись `SkillCatalogRelease` содержит полный manifest, download
(HTTPS без userinfo/fragment) и manifestSha256. Пара id/version уникальна;
несколько версий одного id в каталоге допустимы. Каталог проверяют отдельно
от полного графа выбранных зависимостей. validateRelease сверяет контрольную
сумму и совпадение всех метаданных каталога с загруженным манифестом.
Индекс каталога сам по себе не является списком доверенных издателей.

## Целостность, совместимость и пути

JVM-реализация: [SkillPackageValidator.kt](../shared/src/jvmMain/kotlin/io/aequicor/magicpaper/data/skills/SkillPackageValidator.kt).

Контрольная сумма версии — SHA-256 **точных исходных байтов манифеста**.
Канонизация JSON не требуется: изменение пробелов также создаёт другой digest.
Внутри манифеста SHA-256 связывает каждый путь и размер с байтами файла.
Таким образом нет рекурсивного хеширования манифеста самого себя. Каталожный
digest передаётся валидатору как expectedManifestSha256; при локальном импорте
без независимого digest вычисляется только отпечаток фактически полученных
байтов. SHA-256 архива при наличии можно проверить дополнительно, но он не
заменяет проверку манифеста и файлов.

**Совпавший хеш доказывает только целостность относительно данного отпечатка.**
Он не доказывает безопасность инструкций, автора, лицензию или отсутствие
prompt injection. Злоумышленник может пересчитать все хеши своего пакета.
Даже корректный каталог по HTTPS не повышает пакет до VERIFIED автоматически.

Валидатор отвергает несовместимую схему/хост/платформу, неправильные версии,
повреждённые файлы, неполный/лишний состав, дубликаты путей без учёта регистра,
использование файла как родительского каталога, абсолютные пути, `..`, `.`,
обратные слеши, drive/UNC/ADS, percent escapes, Windows device names и ссылки.
Портативные компоненты пути состоят из ASCII букв, цифр, `_`, `-`, `.`,
не оканчиваются точкой; полный путь до 240 символов. Имена ресурсов Unicode
в v1 не поддерживаются; текст инструкций и метаданных может быть Unicode.

Технические лимиты v1 (решения реализации, не отдельное согласование пользователя):
манифест 256 KiB, до 512 файлов, суммарно 20 MiB payload, до 512 пакетов
в графе или записей каталога. Обход staging ограничен 1024 записями, включая
каталоги. Импортёр обязан ограничивать поток до его материализации в памяти.
validate(entries) принимает только файлы; архивные записи каталогов импортёр
проверяет теми же правилами путей, не передавая как payload. Симлинки,
hardlink-записи архивов и специальные записи отклоняются до распаковки.

validateDirectory предназначен для **приватного staging без конкурентной
записи**. Он проверяет real path, отсутствие симлинков, тип файла и использует
NOFOLLOW_LINKS при открытии. Он не обещает защитить произвольный изменяемый
внешний каталог от подмены родительского каталога между системными вызовами.
Импортёр должен безопасно скопировать выбранные файлы через дескрипторы
в принадлежащий приложению staging; после проверки сделать хранилище версии
неизменяемым. Перед использованием после перезапуска целостность проверяется
снова. Проверка чужого дерева с последующим использованием его исходных путей
не является допустимой интеграцией.

validate проверяет один пакет. validateSet/validateGraph проверяют полное
замыкание зависимостей: отсутствующие версии, конфликтующие версии одного id,
самоссылки и циклы любой длины запрещены. activate повторяет эту проверку для
всего целевого набора; установка отдельного кандидата ещё не обещает полноты
графа. Зависимости проходят такие же проверки доверия и согласия, как корень.

## Состояния, обновления и согласие

Реализация: [SkillReleaseStore.kt](../shared/src/commonMain/kotlin/io/aequicor/magicpaper/domain/SkillReleaseStore.kt).

| Состояние | Значение |
| --- | --- |
| Отклонённый импорт | Нарушена структура/целостность/совместимость; не добавляется в installed. Загрузчик может сохранить диагностическую запись отдельно. |
| installed / QUARANTINED | Байты проверены, версия сохранена как кандидат; инструкции не попадают в контекст. |
| installed / VERIFIED | Есть локальная проверка происхождения, лицензии и содержимого с reviewer/evidence, привязанная к checksum. Это кандидат, ещё не активная версия. |
| active | Отдельная карта id → id@version, прошедшая проверку полного графа и явное подтверждение изменений. |
| previousActive | Предыдущая полная карта активных версий для атомарного отката. |

У id могут быть несколько установленных версий и не более одной активной.
Повторная установка одинакового id/version/checksum идемпотентна; подмена
содержимого под прежним id/version отвергается. Редактирование, локальный опыт
и обновления создают новую версию. Данные старой версии не перезаписываются.

Каждый пакет, включая встроенный/локальный, начинает в карантине. Ни заполненное
origin, ни license=MIT, ни подпись/хеш не дают автоматической активации.
Неизвестное происхождение **или** лицензия блокируют активацию, пока локальный
проверяющий не подтвердит оба и содержимое. Положительная проверка содержит
обоснование/источник установленного авторства и лицензии; при неопределённости
соответствующий флаг остаётся false. У исходного манифеста эти поля могут
оставаться null: уточнение хранится в локальном evidence, а не изменяет digest.
Review не принимается из манифеста, каталога или импортированного профиля.
UI не должен превращать обычное «установить» в положительные review-флаги.

Предпросмотр обновления показывает старую/новую версию, diff инструкции,
ресурсов, происхождения/лицензии, совместимости, зависимостей и разрешений.
SkillActivationConsent связывает подтверждение с generation текущего снимка
и точными checksum **всего** целевого набора. Любая установка/проверка/активация
после предпросмотра делает согласие устаревшим. Для удаления из активного набора
также нужен просмотр изменения. Понижение версии разрешено только тем же явным
переходом, без неявного выбора «последней подходящей».

Новые разрешения вычисляются относительно прежней активной версии **того же
навыка**. Разрешение другого навыка не даёт согласия этому. На первой активации
новыми считаются все разрешения; при откате возвращаемые разрешения также могут
быть новыми относительно текущей версии. Каждое новое разрешение должно быть
в consent.permissions; расширение зависимостей не обходит этот барьер.
Этот набор означает согласие на декларацию возможностей, а не выдачу OS-прав:
runtime обязан отдельно применять ограничения проекта, сети и инструментов.
RUN_PROCESS не разрешает install-скрипты/автозапуск кода пакета.

## Проверка четырёх источников

Эти правила обязательны для следующих транспортных адаптеров. Валидатор данного
этапа не выполняет DNS, HTTP, Git или распаковку; синтаксически допустимый URL
не является подтверждением разрешённого сетевого адреса.

1. Локальный каталог SKILL.md: явный выбор пользователя, безопасная копия
   в staging, полный список ресурсов. Если манифеста нет, импортёр формирует
   его после предпросмотра id/version/описания. Неизвестные автор/лицензия
   остаются неизвестными; не подставлять «доверенный локальный» или MIT.
2. ZIP: проверить все пути/типы/дубликаты до записи; запрет symlink/hardlink,
   шифрованных и вложенно распаковываемых архивов. Лимит загрузки 5 MiB,
   распаковки 20 MiB и 512 файлов контролируется по фактическим потокам,
   независимо от размеров в заголовках. Не извлекать поверх активной версии.
3. Git-репозиторий: только явный сетевой импорт по HTTPS; фиксировать полный
   commit id, а не branch/tag как идентичность. Отключить hooks, submodules,
   LFS/smudge/clean filters, credential helpers и произвольные Git transports;
   не исполнять конфигурацию репозитория. Получать ограниченное дерево выбранного
   коммита; применять те же лимиты и файловые проверки. Branch/tag разрешено
   разрешить в commit только как часть явного предпросмотра импорта/обновления.
4. HTTPS-пакет: явное действие пользователя; проверка TLS, начального URL,
   каждого редиректа и фактического адреса соединения. Запрет userinfo,
   перехода на HTTP и private/loopback/link-local/reserved адресов IPv4/IPv6,
   включая IPv4-mapped IPv6. DNS проверяется при соединении, не только заранее;
   защита от rebinding и ограничение редиректов/таймаутов обязательны.

Git следует той же политике адресов и редиректов, что HTTPS. Не передавать
авторизацию на другой origin; не сохранять токены URL в origin/evidence/logs.
Импортёр фиксирует фактически наблюдавшиеся URL/commit/digest в локальной
истории проверки отдельно от утверждений автора. Эти ограничения импорта
не изменяют явно настроенный локальный LLM endpoint.

Зависимости не импортируются молча: сначала полный план, источники и согласие
на сеть. Обновления не активируются в фоне. Смена издателя, URL или лицензии
требует новой проверки; прежняя проверка другого checksum не переносится.

## Атомарность и восстановление

SkillReleaseStore — исполняемая эталонная модель в памяти: один Mutex охватывает
проверку generation, доверия, графа, согласия и замену снимка. Все проверки
предшествуют записи; ошибка не меняет active/previousActive/generation.
Снимки возвращают копии карт; метаданные пакета декодируются в новые коллекции.
Параллельные подтверждения одного поколения не могут оба завершиться успешно.
rollback переключает весь граф на previousActive, повторно проверяя доверие,
совместимость и разрешения. Снять доверие с активного пакета можно только после
явного переключения набора с проверкой зависимостей.

Постоянный адаптер следующего этапа обязан реализовать тот же переход:

1. Записать байты новых версий в приватный staging, проверить их, завершить
   запись/fsync и атомарно перенести в неизменяемое хранилище версий на том же
   файловом разделе. Активный снимок пока прежний.
2. Под блокировкой или CAS сверить generation и все предусловия. Одной
   транзакцией записать installed/reviews/active/previousActive/generation.
   Для файлов — временный snapshot, fsync, atomic rename и fsync каталога;
   для БД — транзакция. Одиночный rename без обеспечения долговечности не
   объявлять гарантией при сбое питания.
3. Только после успешного commit публиковать StateFlow/контекст runtime.
   При ошибке записи текущая карта остаётся прежней. После аварии выбирать
   целиком последний завершённый снимок, а не восстанавливать отдельные id.
4. Не удалять версии, достижимые из active или previousActive. GC незавершённого
   staging допустим. Повреждённый snapshot не трактовать как пустую библиотеку;
   остановить активацию и предложить восстановление проверенного снимка.

В этом этапе не заявляется crash durability: файлового адаптера пока нет.
Нельзя подключать существующий read-modify-write JsonSkillRepository как
атомарный адаптер без отдельной реализации транзакций и восстановления.

## Передача следующим этапам

Использовать эти модели как wire/domain контракт; legacy enabled не заменяет
active. Для Android/JS/Wasm нужен эквивалентный байтовый верификатор SHA-256
и тесты платформы; перенос common-моделей не доказывает поддержку импорта.
Проверка кандидатов — локальная, не полномочие текста LLM.

Опыт — локальные проверяемые версии без изменения весов модели. Будущий поток
LLM должен показать точный контекст до 6 сообщений и 24 000 символов без секретов,
провайдера/модель до отправки. Удаление опыта независимо от исходного чата должно
удалять его версии/review/индексы, отменять фоновые задачи и блокировать поздние
результаты через generation/tombstone. Это требования следующего этапа,
не реализованная здесь функция SkillReleaseStore.
