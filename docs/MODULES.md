# Модули приложения

Каждая функция имеет `api` и `impl`. API описывает состояние, команды компонента
и порты; реализации экранов, репозиториев и сервисов находятся в `impl`.
Kotlin-пакеты моделей сохранены при переносе, чтобы не менять имена сериализуемых
типов и существующие форматы данных.

Общая сборка приложения находится в реальном модуле `:app` и каталоге `app/`.
Прежний `:shared` удалён; совместимого alias или перенаправления Gradle project нет.
Платформенные hosts подключают `:app`, а фичи сохраняют отдельные API/impl.

| Модуль | Ответственность |
| --- | --- |
| `:app` | Корень приложения, Koin, навигация Decompose, оболочка окна |
| `:designSystem` | Независимый Paper API и общие визуальные компоненты |
| `:core:logging` | Структурированные уровни ERROR/INFO/DEBUG/TRACE, безопасные поля, ограниченное хранение и платформенный sink |
| `:core:model` | Общие сериализуемые значения и чистые правила планирования, моделей и навыков |
| `:core:platform` | Выбор файлов, импорт/экспорт профилей, общая работа с вложениями черновиков |
| `:core:ai:api` / `impl` | Контракты LLM, поиска и учёта использования; HTTP-адаптеры и исследования описаний моделей |
| `:core:storage:api` / `impl` | Контракты обычного, секретного и долговременного хранения; реализации для платформ |
| `:feature:session:api` / `impl` | Чаты и проектные сессии, история, очередь, планирование и единый backend pi/Codex |
| `:feature:custom-tools:api` / `impl` | Каталог инструментов оркестрации и проверка доступа только из режима планировщика; эффекты выполняет владелец сессий |
| `:feature:settings:api` / `impl` | Настройки, подключения моделей и их секреты, редактирование профилей |
| `:feature:docs:api` / `impl` | Поиск и просмотр встроенной документации |
| `:feature:plugins:api` / `impl` | SPI/реестр плагинов и общие встроенные плагины |
| `:feature:skills:api` / `impl` | Каталог, обучение, установка и локальные/project навыки |
| `:desktopApp`, `:androidApp`, `:webApp` | Создание платформенного окружения и запуск общей оболочки |

Чат и проектное исполнение находятся в `feature/session`. Desktop-чат вызывает
`CodingRuntime.runChat`, который адаптирует сохранённую историю к тому же `run`, что
используют проектные сессии. Пакеты Kotlin, ключи хранилища и ресурсные пути
`coding/*` сохранены для совместимости. `GatewaySessionRuntime` обеспечивает HTTP
на платформах без native-процессов; явный workflow макетов остаётся у `LayoutChatAgent`.

`custom-tools` не владеет историей или процессами. Его `CustomOrchestration` проверяет
режим и передаёт команды через `OrchestrationActions`, связанный в `app` с владельцем
дерева сессий. Фильтрация каталога и проверка вызова обе требуют `PLANNING`.

## Отдельный инструмент верстки

С `-PpaperEditor=true` подключаются JVM-модули `:tools:paper-plugin` (адаптер и
изолированные примеры Paper) и `:tools:paper-editor` (desktop launcher).
`tools/mission-visualization` — Git submodule и отдельная composite build.
Его `:shared` принадлежит внешнему редактору; это не восстановление прежнего
модуля MagicPaper. Сборка приложения не конфигурирует инструмент без флага.
Плагин зависит от публичного Paper API и общего API редактора; обратных
зависимостей у `:designSystem` нет. [Запуск и проверка](../tools/paper-editor/README.md).

Обычный чат использует `LayoutEditor` из `session:api`. `LayoutChatAgent` владеет
генерацией и исправлением по диагностике; JVM-адаптер `DesktopLayoutEditor` — запуском
внешнего процесса и ограниченными файловыми операциями. `app` передаёт выбранный
проект и платформенный адаптер. `ChatSession.layoutProjectId` сохраняет привязку
диалога; восстановление не запускает процессы. Приложение связывается с редактором
через аргументы процесса и JSON/PNG-файлы, без зависимости на реализацию редактора.
Desktop-поставка с `-PpaperEditor=true` включает исполняемый инструмент в ресурсы.

## Направление зависимостей

`api` не зависит от `impl` или `app`. Реализация функции может использовать
своё API, API других функций, инфраструктурные контракты и Paper. Реализации
разных функций не зависят друг от друга. `app` связывает реализации с
контрактами; только платформенные приложения зависят от `app`.

`core/model` и `designSystem` не зависят от модулей приложения. Общие чистые
значения не должны превращаться в контейнер сервисов: исполнение планов,
процессы, репозитории и управление активными задачами принадлежат функции.
`core/logging` не зависит от других модулей; storage API, платформенные порты и
владельцы операций используют его без связи с Koin.
`UsageLedger`, `RequestPinService`, `DossierResearcher` и
`SkillInstructionRuntime` имеют отдельные контракты и реализации.

В тестовых source set допустима сборка нескольких реализаций для интеграционных
проверок. Это не создаёт зависимости производственного кода. Небольшие общие
фикстуры планирования находятся в `testSupport/planning` и подключаются только к
тестам. Архитектурная проверка анализирует вложенные модули и производственный граф.

Фабрики компонентов имеют явные уникальные Koin qualifiers в
`app/src/commonMain/kotlin/io/aequicor/magicpaper/di/FeatureFactoryQualifiers.kt`, используемые и при регистрации, и при
получении. В Wasm имена вложенных `ChatComponent.Factory` и других `Factory`
не различаются по enclosing type в ключе Koin. Нельзя заменять эти qualifiers
непомеченным `get()`. Koin запрещает overrides при загрузке модулей; common
runtime-тест дополнительно проверяет конкретный тип каждой из шести фабрик.
Koin и его qualifiers не входят в feature API.

## Gradle conventions

Включённая сборка `build-logic` содержит `magicpaper.kmp-library` и
`magicpaper.compose-library`. Все `core`/`feature` модули используют эти плагины:
единые версии Kotlin/AGP/Compose берутся из корневого version catalog, а JVM,
Android, JS и Wasm targets, Android SDK и host tests настраиваются один раз.
Compose convention добавляет компилятор и ресурсы Compose поверх KMP convention.
Зависимости между модулями остаются явно записаны в их `build.gradle.kts`, поэтому
архитектурная проверка видит полный производственный граф. Платформенные приложения,
оболочка и дизайн-система сохраняют собственные настройки упаковки и ресурсов.

## Платформы и ресурсы

Все общие модули сохраняют JVM, Android, JS и Wasm targets. Нативные процессы и
файловые адаптеры находятся в `feature/session/impl/src/jvmMain`; недоступные на
платформе возможности поставляются через контракт и платформенную реализацию.

Ресурсы протоколов движков находятся в `feature/session/impl/src/jvmMain/resources/coding`.
Их classpath-пути `coding/*` сохранены. Node-проверки и локальные интеграционные
сценарии находятся в соседнем `src/jvmTest/resources/coding`.
Шрифты и общие визуальные ресурсы принадлежат `designSystem`.

Навигация, черновики, миграции ключей и время жизни владельцев: [NAVIGATION-AND-STATE.md](NAVIGATION-AND-STATE.md).

## Проверки

- `python3 docs/verify-module-architecture.py --self-test` — API/impl, запрет циклов, зависимостей функций от чужой реализации и повторного появления `:shared`.
- `python3 docs/desktop-ui/verify-design-system.py --self-test` — Paper API во всех, включая вложенные, модулях.
- `python3 docs/desktop-ui/verify-map.py --self-test` — актуальность привязки экранов и компонентов к Paper.
- `./gradlew checkMigrationJvm` — JVM-тесты всех модулей и локальные Node-протоколы.
- `./gradlew compileMigrationTargets` — компиляция Desktop, сборка Android APK, полное связывание JS и Wasm.
- `./gradlew verifyMigration` — все перечисленные Gradle-проверки и Android host tests.

Реальные движки проверяются отдельно с явными флагами, например
`./gradlew :feature:session:impl:jvmTest --tests '*PlanningRuntimeIntegrationTest' -Pmagicpaper.pi.it=true -Pmagicpaper.codex.it=true`.
Подробности локальных серверов и ресурсов: [движки](ENGINES.md).

JUnit XML сохраняет имена классов и тестов после переноса. Для сравнения с запуском
исходного checkout используйте `python3 docs/compare-jvm-baseline.py <baseline> .
--output <report.json>`. Скрипт отдельно показывает новые ошибки, изменившиеся
ошибки, устранённые ошибки и тесты, отсутствующие в одном из запусков; исходные
safety-проверки не исключаются из Gradle задач.

Контракт диагностики, redaction и границы хранения: [LOGGING.md](LOGGING.md).
