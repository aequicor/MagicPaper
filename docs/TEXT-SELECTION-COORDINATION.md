## Порядок для ms-targeted

1. Перед первой правкой сверить HEAD, git status и SHA-256 всех пяти файлов
   с baseline. Перечитать актуальные файлы и их diff; baseline — отметка времени,
   а не источник для отката. Не восстанавливать файл из HEAD или прежней копии.
2. При несовпадении SHA-256 повторно прочитать новый текст и diff, установить
   новые пересечения и сообщить планировщику через QUESTION с targetStageId.
   Если изменения несовместимы или их назначение непонятно, согласовать конкретные
   участки до их редактирования; независимые участки можно продолжать.
3. Непосредственно перед каждой правкой перечитать файл; применять минимальный
   контекстный патч к свежему содержимому. Сохранить исходный текст/diff в памяти
   этапа для последующего сравнения. Не использовать reset, checkout, clean,
   перезапись целых общих файлов или удаление untracked-файлов.
4. Сразу после патча просмотреть разницу с прочитанным состоянием и текущий
   git diff. Проверить сохранность подключения планирования и поведения,
   перечисленного выше. Если файл изменился параллельно, перечитать и согласовать
   пересечения; не накладывать прежний патч вслепую.
5. По завершении снова сверить все пять файлов, общий git status и собственные
   изменения. Для изменённых файлов выполнить проверку пробелов и подходящие
   проверки реализации из готовой диагностики. Обновить перечень фактически
   затронутых путей и исходное/конечное состояние в отчёте этапа; baseline этого
   этапа не перезаписывать. При расширении списка повторить сверку с соседом.
