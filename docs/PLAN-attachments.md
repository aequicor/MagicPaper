# План: вложения — изображения и файлы в чате и кодинг-сессиях

Цель: пользователь может прикрепить файлы к сообщению (кнопка со скрепкой, как в
современных ИИ-клиентах): **изображения** уходят модели напрямую и показываются в ленте,
**текстовые файлы** подмешиваются в сообщение содержимым, в **кодинг-сессиях** файлы
доступны агенту на диске. Всё — в общем коде KMP (jvm/web/android).

Ограничения проекта: KMP без платформенных библиотек выбора файлов, хранение истории —
`KeyValueStore` (десктоп — файлы, браузер — localStorage), без материальных иконок
(текстовые глифы), стиль — пастельный минимализм.

---

## 1. Модель данных (домен)

| Что | Где | Решение |
|---|---|---|
| Вложение | `domain/Attachment.kt` | `Attachment` (id, имя, MIME, размер, содержимое в base64, вид) + `AttachmentKind`: `IMAGE` / `TEXT` / `FILE` |
| В журнале кодинг-сессии | `CodingMessage.attachments` | лёгкие `AttachmentMeta` (имя, MIME, размер, вид, путь) — сам файл на диске, журнал не раздувается |
| В чате | `ChatMessage.attachments` | полные `Attachment` — превью рендерится прямо из истории |
| К модели | `LlmMessage.attachments` | только у текущего запроса; история идёт текстом, чтобы каждый ответ не раздувал контекст |
| Выбор файлов | `FilePicker` (порт) | `PickedFile(name, mimeType, bytes)`; лимиты решает платформа |

Лимиты: до `MAX_ATTACHMENTS_PER_MESSAGE = 8` вложений на сообщение; потолок размера
одного файла задаёт платформа (десктоп — 20 МБ, браузер — 3 МБ из-за квоты localStorage).

MIME: платформа сообщает сама; фолбэк — по расширению (`mimeFromName`). Тип вложения:
по MIME и расширению (`Attachment.kindOf`): `image/*` и картинки по расширению → `IMAGE`;
`text/*`, набор «кодовых» и конфигурационных расширений → `TEXT`; остальное → `FILE`.

## 2. Проведение в модель (чат)

`LlmPayloads` строит мультимодальные сообщения для каждого формата:

- **Изображения** — инлайн в формат провайдера:
  - OpenAI-совместимый: `content` — массив `{type: text}` + `{type: image_url, image_url.url = "data:<mime>;base64,<…>"}`;
  - Anthropic: блоки `{type: text}` + `{type: image, source: {type: base64, media_type, data}}`;
  - Google: `parts` — `{text}` + `{inlineData: {mimeType, data}}`.
  Массив появляется только при картинках; иначе контент — строка.
- **Текстовые файлы** — содержимое добавляется в текст сообщения (`Файл <имя>:\n<содержимое>`).
- **Бинарные файлы** в чат не отправляются — в текст добавляется примечание
  «(Приложены файлы без передачи содержимого: …)», чтобы модель знала о контексте.
- Системные промпты и история ассистента — только текстом (провайдеры не принимают
  изображения в системные сообщения; повторная отправка истории раздувала бы контекст).

Изображения из истории не переотправляются в последующих запросах — вложения несёт
только сообщение, в котором они были прикреплены.

## 3. Кодинг-сессии

`CodingRuntime.run(…, attachments)` принимает вложения; пи-рантайм:

1. раскладывает файлы в изолированную папку `~/.MagicPaper/coding/uploads/<id сессии>/`
   (вне папки проекта — мусор не засоряет репозиторий; уникальные имена защищают от
   коллизий), очищает папку при удалении зависимостей;
2. дописывает в промпт абсолютные пути — агент читает файлы своими инструментами
   (работает и с текстом, и с изображениями через его собственные возможности).

В журнал (`CodingMessage`) попадают только `AttachmentMeta` — двоичные данные не
дублируются в хранилище на каждое сообщение.

## 4. Платформенный выбор файлов

- **Десктоп (jvm)**: `DesktopFilePicker` — `JFileChooser` с множественным выбором;
  MIME по `Files.probeContentType` с фолбэком по расширению; фильтр по размеру.
- **Браузер (js/wasmJs, общий webMain)**: `BrowserFilePicker` — скрытый
  `<input type="file" multiple>`; содержимое читается `FileReader.readAsDataURL`
  и разбирается из base64 — строки одинаково проходят межплатформенный мост
  в обоих целях без межслойных типизированных массивов.
- **Android**: `NoopFilePicker` — интерфейс честно сообщает, что выбор недоступен;
  кнопка скрепки показывает уведомление.

## 5. Пользовательский интерфейс

- Кнопка 📎 рядом с полем ввода в чате и в кодинг-сессиях.
- Строка выбранных вложений над полем ввода: миниатюры изображений, глиф и имя для
  остальных, размер, крестик удаления.
- В ленте чата у сообщений пользователя: галерея превью (изображения рендерятся из
  истории `decodeToImageBitmap`), клик — просмотр в полном размере.
- В ленте кодинг-сессии у запросов: компактные чипы «глиф · имя · размер».
- Отправка работает при пустом тексте, если есть вложения; лимит 8 файлов —
  уведомлением.

## 6. Тесты

- `AttachmentTest`: определение типа по MIME/расширению, видимость в чате,
  метаданные без содержимого, обратимость base64, человекочитаемый размер.
- `LlmPayloadsTest`: изображения → блоки провайдера (data-URL / base64-источник /
  inlineData), текстовые файлы → подмешивание в текст, бинарные → примечание,
  без вложений формат запроса не меняется.
