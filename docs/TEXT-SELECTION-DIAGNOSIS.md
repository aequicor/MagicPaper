# Диагностика выделения сообщений

Дата: 2026-09-07. Этап ограничен диагностикой; поведение приложения не изменено.

## Фактическое состояние

Перед анализом выполнены `git status --short` и `git diff`: рабочая папка содержит
чужие изменения планирования, включая `CodingScreen.kt`, `App.kt` и новый
`PlanningChatMessage.kt`. Они учтены и сохранены. В компонентах сообщений выделение
пока не подключено. Единственный найденный `SelectionContainer` в commonMain —
просмотр prompt попытки в `plugins/builtin/DecisionPlanningPlugin.kt:488`;
этот контейнер не охватывает сообщения чата или проектов.

Все пути ниже, кроме явно указанных модулей, относительно
`shared/src/commonMain/kotlin/io/aequicor/magicpaper/`. Номера строк относятся
к текущей рабочей копии; при следующем этапе искать также по имени функции.

## Desktop-стек и среды

- Kotlin Multiplatform 2.4.10, Compose Multiplatform 1.11.1, Material3
  1.11.0-alpha07: `gradle/libs.versions.toml`.
- Общий Compose UI в `shared/commonMain`, JVM target в `shared/build.gradle.kts`;
  desktop — JVM-приложение Compose Desktop с AWT-окном и JetBrains Runtime 21,
  `compose.desktop.currentOs`, `desktopApp/build.gradle.kts`.
- Markdown — `com.mikepenz:multiplatform-markdown-renderer-m3` и `-code` 0.41.0;
  синтаксическая подсветка через Highlights в `ChatMarkdown.kt`.
- Windows: MSI, режим JBR custom title bar либо системная рамка при отсутствии
  поддержки; macOS: DMG, системная рамка; Linux: DEB, собственная Compose-рамка.
  Основания: `README.md`, `desktopApp/build.gradle.kts`,
  `desktopApp/src/main/kotlin/io/aequicor/magicpaper/DesktopWindowMode.kt` и `main.kt`.
- Минимальные версии desktop ОС и гарантия для конкретных Linux DE,
  X11/Wayland в просмотренной конфигурации не заданы. Поддержка семейств ОС
  заявлена проектом; фактические GUI-проверки на этих ОС этим этапом не выполнены.
- Также есть Android, JS и Wasm browser targets. Изменения commonMain затронут
  их; desktop-поведение нельзя подтвердить проверкой только браузера.

Основная причина в коде приложения — обычные `Text` без области выделения.
`DisableSelection`, CSS `user-select` и глобальные перехватчики Copy в UI не найдены.
Это Compose UI, а не HTML/DOM. Исходники зависимости Markdown в проекте отсутствуют:
внутренние контейнеры, таблицы и жесты библиотеки не проверены. Кнопка копирования
всего кода включена через `showHeader = true` для codeFence/codeBlock; она не
подтверждает возможность выделить произвольный фрагмент кода.

## Жесты и границы решения

- `MessagesList` (ChatScreen:76) и `CodingChat` (CodingScreen:650) используют
  `LazyColumn` и `stickToBottom`. `ui/components/ChatScroll.kt:41` учитывает
  прокрутку ленты, но не состояние выделения. Рост ответа на нижней границе может
  сдвигать текст при выделении — это риск для GUI-проверки, а не доказанный дефект.
- Корневой `App.kt:123–124` размещает экраны отдельно от верхней панели
  `WindowTitleBarArea` (155) / `WindowDragArea` (169).
  `shared/src/jvmMain/kotlin/io/aequicor/magicpaper/ui/window/WindowChrome.jvm.kt`
  обрабатывает перемещение окна и Windows hit-test только в заголовке;
  оснований менять его ради выделения сообщений нет.
- `DecisionGraph.kt:107–119` содержит onKeyEvent для стрелок/Home и
  detectTransformGestures для pan/zoom; карточки графа кликабельны.
  Это интерактивный сосед текста в планировании, а не перехватчик всей ленты.
- Кнопки отправки, вложения, ссылки Markdown, checkbox задач, меню и копирование
  блока кода должны сохранить клики. При широкой текстовой области исключать
  управляющие элементы через `DisableSelection` либо вынести их за её пределы.

**Точечный подход применим на уровне архитектуры:** Compose Foundation уже
подключён, новый desktop-стек, доменные изменения и собственный clipboard не нужны.
Основной объём — ChatMarkdown и текстовые ветки двух экранов; для текущей рабочей
копии учесть PlanningChatMessage. Начать с областей одного сообщения/тела шага,
не оборачивать всю LazyColumn или App. Выделение между разными сообщениями и
невидимыми элементами виртуализированной ленты отдельно не обещать. Реальное
выделение через Markdown-списки, таблицы и подсвеченный код требует проверки
библиотеки/GUI; одной обёрткой оно на этом этапе не доказано.

## Примеры и критерии следующей проверки

Одинаковый образец показать **в обоих разделах**: обычный чат и диалог проекта.
Пользовательское сообщение отображает его как plain text; ответ агента — как
Markdown. В проектах повторить для ANSWER в draft и сохранённой ленте, а также
для старого сообщения без steps (там Markdown сейчас не рендерится).

~~~~markdown
Первая строка: Привет, мир! Hello — café, ёжик, 123.
Вторая строка: выделить только «часть текста».

- Первый пункт с **жирным текстом**
- Второй пункт с `inline_code`
  - Вложенный пункт

1. Первый шаг
2. Второй шаг

| Имя | Значение |
| --- | --- |
| Альфа | 42 |
| Бета | текст с пробелами |

```kotlin
fun main() {
    val text = "Привет"
    println(text)
}
```

> Цитата для выделения.

- [ ] Задача

[Ссылка](https://example.com)
~~~~

| Проверка в каждом разделе | Ожидаемый результат после реализации |
| --- | --- |
| Drag слева направо и обратно; двойной клик по слову | Видимое выделение нужного фрагмента; перетаскивание не двигает окно. |
| Копировать Cmd+C на macOS, Ctrl+C на Windows/Linux, вставить в простой редактор | Совпадают выбранные символы, кириллица, пробелы и переносы; текст кнопок/статусов не добавляется случайно. Проверку выполнять после фокуса в сообщении, а также после фокуса в composer. |
| Выделить часть пункта и протянуть через несколько пунктов | Выделяется текст пунктов, сохраняется порядок. Отдельно записать формат маркеров в clipboard: rendered text не обязан воспроизводить исходный Markdown. |
| Выделить часть ячейки и протянуть через строку/несколько строк таблицы | Ячейки доступны, порядок текста корректен; записать фактические разделители строк/колонок. Проверить широкую таблицу и прокрутку. |
| Выделить часть строки кода и несколько строк с отступами | Копируется выбранный фрагмент; отступы/переносы сохраняются. Шапка не попадает в код; кнопка копирования всего блока продолжает работать. Проверить длинную строку. |
| Длинное сообщение больше viewport, колесо/трекпад, изменение размера окна | Доступен текст за пределами первого экрана, прокрутка работает; не требовать выделения некомпозированных соседних сообщений. |
| Потоковый ответ, выделение у конца и после ручной прокрутки вверх | Проверить стабильность выделения и clipboard при росте; отсутствие неожиданного возврата вниз после ручной прокрутки вверх. |
| Ссылка, вложение, checkbox и отправка | Клики сохраняют прежнее действие, текст composer редактируется и копируется. |

Дополнительно в проектах: раскрыть THINKING и TOOL/EXEC, выделить тело и скопировать;
оно не сворачивается от drag, заголовок по клику сворачивает. Повторить ERROR/INFO,
activity старого журнала и нижнюю панель размышления. В режиме планирования
проверить цель/вопрос/варианты/отправленный комментарий, сохранность radio/checkbox,
кнопок подтверждения и pan/zoom графа. Выполнить desktop-матрицу macOS,
Windows (JBR и fallback), Linux; X11/Wayland фиксировать по доступной тестовой среде.
