# Проектные подключения и coding: безопасный режим

> Ниже сохранён исторический контракт строгого запрета. После согласования пользователем opt-in доверенного текста добавлен [новый режим и отчёт проверки](skills-project/trusted-text.md). Он сохраняет штатную политику backend, но не обещает отдельную ACL пакета или абсолютный запрет команд из инструкции.

2026-09-08. Реализовано управление проектными пакетами. Применение пакетов
в Pi/Codex намеренно заблокировано до доказанной защиты адаптеров. Это **не**
подтверждение полной матрицы R01–R15 или успешной живой передачи инструкций.

## Контракты

- «+» композера любого coding-чата, включая planning/stage, содержит SKILLS.
  Модальное окно получает текущий projectId; при смене проекта закрывается.
  Панель читает тот же LocalSkillRepository, что существующий локальный плагин.
  Разделы: «Подключённые», «Созданы автоматически», «Библиотека».
  Показываются версии, полный checksum, наблюдаемый и заявленный источник,
  лицензия, review, improvement, заявленные разрешения и причины блокировки.
- `SkillReleaseSnapshot.projects`: отдельные постоянные записи
  `projectId -> {id@version: checksum}` в атомарном snapshot.json общего
  хранилища. Сами releases не копируются ни в чаты, ни в проекты.
  Старый snapshot без projects читается с пустой картой. Backup/restore
  включает привязки; удаление используемого релиза отвергается.
- `bindProject`: согласие связано с generation и полным набором checksum.
  Проверяются review, improvement baseline, граф точных зависимостей и отдельное
  согласие на новые разрешения. UI позволяет собрать набор и затем подтвердить;
  отмена preview ничего не записывает. Подтверждение не предоставляет доступ.
- `projectInstructions`: возвращает точные ID/version/checksum/text только
  закреплённых проверенных пакетов; повторно проверяет байты всех файлов.
  Изменение библиотеки/привязок не изменяет уже полученный снимок.
- DesktopCodingRuntime получает снимок перед выбором реального маршрута,
  в том числе при продолжении engine-сессии и для planning-исполнителей.
  При непустом составе выдаёт host-owned Notice с run/project/session/adapter,
  полными версиями/checksum и статусом «Передано: нет», затем Failed/Finished.
  Ни Pi.run, ни Codex.runCoding не вызываются. При повреждении — отказ до
  транспорта; CancellationException не превращается в ошибку модели.
  Пустой состав фиксируется Notice, обычный маршрут и его инструменты сохраняются.
- Защита закрыта без переключателя обхода: Pi не имеет доказанной файловой/сетевой
  изоляции shell; Codex не имеет доказанного запрета пакетного исполнения и
  нативной загрузки навыков. Пакетные инструкции не помещаются в system/developer
  prompt, скрипты не запускаются. Политика инструментов Codex не изменялась.
  Отключение исключает пакет из следующего снимка, но очистка истории ранее
  **реально переданных** пакетов не реализована: таких передач этот путь не делает.
- D2/обучающий payload не изменён. Аудит остаётся в coding-ленте через существующий
  recorder и не становится обучающими данными. Review пакета и проверка результата
  задачи различаются явно; новая проверка результата не заявляется.

## Доказательства и пределы

ProjectSkillsTest проверяет точный текст снимка, restart, A→B→A, изоляцию нового
проекта, отключение, обновление при сохранённом снимке, карантин, разрешения,
устаревшее согласие, отсутствие записи отменённого preview, повреждённый checksum,
прерывание commit, backup/restore, защиту удаления, cancellation и отказ обоих
маршрутов при start/resume. Тест отказа проверяет receipt с точными версиями и
checksum и отсутствие запуска транспорта; это **не тест передачи текста в CLI**.
Рендер панели использует реальный временный репозиторий и переходы A→B→A.

Повторно запускаются ProjectsPanelCollapseTest, ProjectsPanelStickyTest,
CodingChatScrollTest, CodingComposerRenderTest, CodexCodingPermissionsTest и все
`data.skills.*`. Полный пользовательский click-through меню/подтверждения,
живые Pi/Codex, OS-перехват и удаление ранее переданного контекста — NOT_RUN.

Команда финальной проверки:

```sh
./gradlew --no-daemon :shared:jvmTest --tests 'io.aequicor.magicpaper.data.skills.*' --tests '*ProjectsPanel*Test' --tests '*CodingChatScrollTest' --tests '*CodingComposerRenderTest' --tests '*CodexCodingPermissionsTest' :desktopApp:compileKotlin
```

Результат и SHA-256 проверенного дерева записываются в
[project-verification.json](skills-project/project-verification.json).
Первый запуск Gradle был остановлен песочницей (служебный socket); штатное
повышение разрешений одобрено. Использован обычный ~/.gradle, без offline.
Ошибки компиляции callback и импорта Compose исправлены перед финальной проверкой.
