# Проектные SKILLS: согласованный режим доверенного текста

[Итоговая матрица, A→B→A, пересечения и конкретные live-блокеры](final-matrix.md): регрессия после UI-интеграции отката — 158 tests, 0 failures/errors, 2 skipped; живой Pi/Codex остаётся NOT_RUN.

## Изменённый контракт

Пользователь через оркестратора разрешил opt-in доверенный текст «в соответствии с политикой безопасности backend coding agent». Это **не** подтверждение исходного абсолютного запрета выполнения команд из SKILL.md. Приложение не устанавливает пакет как расширение, не запускает его установщики и не передаёт пути к пакетным скриптам. Агент может выполнить команды из текста своими обычными инструментами. Заявленные разрешения пакета не являются отдельной ACL. Политики Pi/Codex, shell, approvals, сеть и filesystem-конфигурация этим изменением не расширяются и не отключаются. D2 не менялся.

Информационная иконка вместо «+» согласована ранее. Чужие изменения меню, scrolling, RequestPins, Markdown, черновиков и оркестрации сохранены. Вспомогательные исправления компиляции соседних правок: в CodingScreen добавлен отсутствовавший импорт CodingSession; в CodingDraftUpdatesTest явно передан обязательный isError=false. Другая логика этих файлов не менялась этим исполнителем.

## Реализация

- В SKILLS есть отдельная настройка доверенного текста для подключённого состава и unchecked checkbox в preview изменения. Показаны точные checksum и риск выполнения команд; согласие не наследуется автоматически при обновлении. Без согласия подключение сохраняется, но применение блокируется с причиной.
- `SkillReleaseSnapshot.projectTextConsents` хранит `projectId -> точные pins`. Запись атомарна с проектными привязками и привязана к generation. Старые snapshots читаются без opt-in. Один репозиторий, без копирования библиотеки в чаты.
- `projectCodingSelection` под одним mutex читает привязки, согласие и проверенные байты. Карантин и повреждения по-прежнему отвергаются до транспорта. Снимок запуска не зависит от последующих обновлений.
- Наличие ключа projectTextConsents сохраняется после отзыва/отключения с пустым набором. В таком проекте **каждый** запуск получает пустой engine-session ID, включая продолжения и новые чаты. Старые сообщения не добавляются к prompt этим путём. Цена консервативного решения — потеря engine-истории даже при неизменном составе; это явно написано в UI.
- Восстановление backup сбрасывает text-consent и сохраняет необходимость новой engine-сессии для затронутых проектов: старый backup не должен вернуть загрязнённую историю после более позднего opt-in.
- `prepareCodingSkillInput` сериализует ID/version/checksum/text/declaredPermissions в JSON внутри **пользовательского** prompt. Этот вход используется вызовами реальных `PiCodingRuntime.run` и `CodexAppServerOpenAiSubscription.runCoding`, включая Codex provider bridge. System/developer prompt, переменные окружения, расширения и инструменты не берутся из пакета.
- Перед preflight сохраняется неизменяемый `coding-runs/<runId>.json` в общем локальном хранилище: состав, полный текст инструкций, project/session/adapter, режим и статус `prepared-not-confirmed`. Запись не включает задачу, историю, вложения или вывод и не подключена к D2/обучению. Повторная запись того же runId отвергается. Эти audit-файлы не входят в package backup; политика автоматической очистки пока не добавлена.
- Квитанции создаёт приложение: сначала «подготовлено», затем при передаче аргументов функции адаптера — «вход передан адаптеру». Это не утверждение о приёме моделью или успешном результате задачи. При отказе preflight квитанции передачи нет.

## Проверки и границы доказательства

`ProjectSkillsTest` дополнен:

- trusted consent после закрытия/повторного открытия репозитория, изоляция другого проекта;
- обновление сбрасывает opt-in, не меняет уже полученный снимок;
- отключение и повторное открытие сохраняют fresh-session;
- разбор подготовленного JSON и точное сравнение ID/version/checksum/text для обоих значений engine;
- отсутствие прежнего текста и engine ID после отключения;
- отсутствие передачи без согласия;
- отказ preflight обоих движков сохраняет подготовленные audit-файлы без задачи;
- cancellation не становится ошибкой модели, audit-файл неизменяем, согласие сохранено;
- восстановление backup до opt-in не разрешает resume загрязнённой истории.

Это проверки хранилища, подготовленного входа и отказа перед транспортом. **Не** wire-тест реального Pi/Codex и не доказательство отсутствия старого контекста в реальном backend. Нативные AGENTS.md/skills, память backend и изменения файлов, сделанные предыдущим запуском, не удаляются. Полная исходная приёмка не заявляется.

Прочитана локальная документация Pi: README, skills.md, json.md, session-format.md. Документация подтверждает риск исполнения команд навыка и различие новых/продолжаемых сессий; это не замена живому тесту конкретной версии backend.
