# Диагностика приложения

`:core:logging` не зависит от других модулей. `AppLog` в пакете
`io.aequicor.magicpaper.logging` предоставляет `info`, `debug`, `error` и `trace`.
Это общий sink диагностики, без service locator или глобального Koin graph.
`AppLogger` позволяет изолировать уровень, sinks и историю в тестах.

Порядок уровней: `ERROR → INFO → DEBUG → TRACE`, по умолчанию `INFO`. TRACE
включается явно через `AppLog.level` и не активируется после ошибки. Его lambda
не вызывается, пока уровень выключен. Передавайте известные credentials в
`knownSecrets`, если подробная диагностика содержит свободный текст; не передавайте
в неё данные секретных полей без этого контекста.

Обычные события содержат machine codes, а не названия, сообщения, prompts, bodies,
URLs, headers, пути или ключи хранилищ. Неизвестные поля исключаются. ID-поля
(`operationId`, `correlationId`, `visitId`, `sessionId`, `projectId`, `requestId`,
`profileId`, `entityId`, `journalId`, `windowId`, `tabId`, `planId`, `draftId`)
становятся стабильными непрозрачными значениями для корреляции; это не
криптографический идентификатор и не способ хранения credentials. Полный allowlist
метаданных определён в `AppLog.kt`.

`error(component, event, cause, fields)` сохраняет до шести типов исходной цепочки
причин. Logger не читает сообщения или stack traces, не изменяет исключение и не
заменяет обработку ошибки её владельцем. Владелец сохраняет ввод и доступный UI
error/retry; распространённую ошибку не следует заново логировать на каждом слое.
`error(component, event, fields)` фиксирует отказавшую операцию, когда исключения
нет: отказ транспорта или исход, сообщённый движком. Типы причин при этом пусты.

Вызовы инструментов логирует владелец записи вызова: `ToolExecutor.execute` для
инструментов приложения (там есть исходная причина) и `ToolExecutor.recordNative`
для вызовов самого движка. Компонент `coding.tool`, события `call.started`,
`call.progress`, `call.completed`, `call.cancelled`, `call.failed`,
`call.outcome_unknown`; поля `tool`, `category`, `kind` (`application` или
`native`), `mode`, `phase`, `failure`, `durationMs` и непрозрачный `entityId`.
Аргументы, вывод и тексты ошибок в обычные уровни не попадают: они остаются в
квитанции вызова для UI, а в диагностику идут только как `TRACE`-полезная нагрузка
с маскированием и ограничением размера. Отказ транспорта MCP логируется отдельно в
`coding.tools` и `coding.questionnaire`.

TRACE маскирует известные секреты, credential assignments, auth/cookie headers,
типовые ключи, JWT и URLs до ограничения размера. Это дополнительная защита:
произвольное секретное значение без имени или известного значения невозможно
надёжно классифицировать по тексту. Нельзя использовать TRACE как необработанный
дамп неизвестных секретных форм или протоколов.

История приложения хранит последние 128 записей. В записи не больше 24 полей;
metadata ограничены 160 символами, TRACE — 2048 (явно настраиваемый максимум 8192).
Обработка detail сканирует не больше 64 KiB. Платформенные sinks пишут одну JSON
строку. Если передано более 128 известных секретов или один из них больше лимита
сканирования, detail скрывается целиком. Платформенные sinks используют
stdout/stderr на JVM, Logcat на Android, console на JS/Wasm. Дискового
журнала приложение не создаёт; дальнейшее хранение stdout/Logcat контролирует host.
При сбое sink используется безопасная резервная запись, при сбое обоих sinks
ошибка остаётся в ограниченной памяти logger и не меняет результат операции.
Построение и санитарная обработка записи тоже имеют границу ошибки: если metadata
или платформенный Regex engine недоступны, logger создаёт `entry_preparation_failed`
с типами причин, без повторного обращения к исходным полям. Regex создаются лениво
внутри этой границы; quoted fields используют синтаксис, совместимый с Unicode
режимом JavaScript. В аварийной записи timestamp равен 0, если подготовка не завершена.

Проверки владельца: `./gradlew :core:logging:jvmTest`; после изменения common API
также компиляция Android, JS и Wasm. Тесты проверяют уровни, ленивость TRACE,
redaction, исключение свободных полей, цепочку типов причин, границы памяти и
сбои sinks. Платформенная компиляция не заменяет наблюдение логов работающего host.
