# Компьютер и приложение в фоне

В **Настройки → Движки → Компьютер и приложения** независимо задаются два режима:
«Весь компьютер» (`computer`) и «Приложение в фоне» (`application`). Для каждого
есть «Выключено», «Просмотр» и «Управление». Сохранённая настройка применяется
при следующем явном запросе в кодинг-сессии или обычном чате; включать доступ
перед каждым сообщением не нужно. Для визуального анализа нужна модель с
поддержкой изображений и вызовов инструментов.

Настройка — политика, а не сохранённое разрешение конкретному запуску. Временное
разрешение получает одна сессия после проверки владения и готовности движка.
Завершение запроса, остановка, «Отключить», удаление и shutdown отзывают его.
Смена политики отзывает текущий доступ **до записи настроек**; ошибка сохранения
не включает его обратно. Загрузка настроек, импорт профиля, автоматическое
восстановление и очередь из предыдущего запуска доступа не выдают. Явное
продолжение пользователя может получить новый доступ. Этапы, research и workers
не приобретают его автоматически. Экспорт/импорт обнуляет обе политики.

В панели кодинг-сессии «Отключить» работает и во время операции. «Снимок» доступен
только для всего компьютера, не для application-only; превью можно увеличить.
В обычном чате остановка запроса также отзывает доступ.

## Возможности и платформы

- Codex через подписку ChatGPT: локальный MCP подключается при старте и продолжении
  coding-сессии. Другие права Codex, включая сетевую песочницу, сохраняются.
  Перед продолжением завершённая сессия выгружается из app-server, чтобы применить
  новый MCP endpoint: обычный resume уже загруженной сессии сохраняет старый клиент.
  История остаётся в rollout и восстанавливается при resume.
- pi: встроенное расширение регистрирует оба инструмента для выбранного
  API-провайдера, включая Anthropic, OpenAI-совместимые серверы и Google.
- macOS, Windows и Linux X11: PNG, выбор монитора, движение и нажатия мыши,
  двойной клик, перетаскивание, вертикальная прокрутка, текст и сочетания клавиш.
- Application-use: macOS 14+ — Accessibility/AX и ScreenCaptureKit;
  Windows — UI Automation и `PrintWindow`. Выбирается конкретное окно из `windows`.
  Снимок закрытого другим приложением окна **не** заменяется обрезкой общего экрана.
  Свёрнутые/защищённые окна и неподдерживаемый захват возвращают ошибку.
- Application-use не фокусирует окна и не использует общую мышь, клавиатуру или
  буфер обмена. Пользователь может работать в другой программе. Целевая программа
  сама может открыть диалог или активироваться вследствие своего действия — AX/UIA
  не являются изолированным рабочим столом. Custom canvas без доступных элементов
  не поддерживается; fallback на глобальный ввод запрещён.
- Wayland, Android и браузер: управления системным рабочим столом нет.
  Application-use на Linux не предоставляется.
- Это снимки по запросу, а не непрерывное видео. Действия выполняются на настоящем
  рабочем столе пользователя; приложение не создаёт изолированный виртуальный экран.

На macOS нужны системные разрешения «Запись экрана» и, для ввода,
«Универсальный доступ». Приложение проверяет разрешения перед операциями и показывает,
где их включить. После разрешения записи экрана может потребоваться перезапуск.
При запуске из IDE разрешение может относиться к Java/IDE. Windows UAC и защищённые
экраны не поддерживаются; системные ограничения не обходятся.

Снимки включают видимые окна и передаются выбранной модели. MagicPaper держит
последнее превью в памяти и очищает при отключении. Отдельных файлов скриншотов
не создаёт; движки Codex/pi могут сохранять изображения в собственной истории
инструментов, а хранение на стороне провайдера определяется его настройками.
Только `computer.type` использует временную вставку Unicode через буфер обмена с восстановлением
прежнего содержимого. История буфера обмена ОС или другие менеджеры буфера могут
сохранить вставленный текст.

## Устройство

`ComputerUse` — общий порт и временное состояние UI. `DesktopComputerUse`
сериализует операции, проверяет владельца и поколение разрешения. `AwtComputerDesktop`
выполняет захват и ввод через Java Robot; на macOS JNA проверяет разрешения системы.
JVM-модуль `jdk.httpserver` включён в упакованный desktop runtime.

`ApplicationUse` проверяет одноразовый semantic snapshot; `NativeApplicationDesktop`
владеет отдельным процессом на время разрешения. Нативные AX/UIA ссылки остаются в
этом процессе и повторно проверяются перед действием: окно, PID/start time,
принадлежность элемента, доступные действия и текущее значение. Пароли не выдаются
в semantic tree и не доступны для ввода. Данные интерфейса недоверенные, не инструкции.

Запрос/ответ — JSON-lines через унаследованные pipes, без HTTP-сервера у helper.
Текст не попадает в command line. Чтение **и запись** ограничены 25 секундами;
ответ — 8 МиБ, дерево — 500 элементов/24 уровня, отображаемые значения — 1000 символов.
Отмена/отзыв убивает процесс, не ожидая зависшего провайдера; неизвестный исход
не повторяется автоматически. Диагностика содержит operation/session/generation,
action и тип ошибки, но не содержимое окон или ввод.

Swift helper компилируется `:feature:session:impl:bundleApplicationUse` на macOS
(Xcode CLI tools нужны машине сборки, не пользователю). Бинарник извлекается в
стабильный каталог `~/.MagicPaper/coding/native/application-use/<sha256>/`, проверяется
по bundled bytes и получает права 0700. Разрешения TCC выдаются этому helper/его
responsible process; обновление или подпись пакета могут потребовать согласия заново.
Windows запускает checksum-verified bundled script системным Windows PowerShell;
`-ExecutionPolicy Bypass` действует только на этот процесс, не меняет машинную
политику и не отменяет enterprise policy/UAC. Упаковка, подпись и реальные разрешения
требуют отдельной проверки установленного приложения на каждой ОС.

Каждый активный запрос получает MCP endpoint на `127.0.0.1` со случайным портом и
случайным 256-битным bearer token. HTTP-запросы из браузера (`Origin`) отклоняются,
размер входа ограничен 64 КиБ. Endpoint закрывается в `finally`; старое поколение
разрешения не получает доступ после повторного включения. Настройка Codex при
выключенном доступе явно отключает прежний endpoint. Расширение pi получает
адрес и токен через окружение, исходник расширения не содержит токенов.

Инструмент `computer` принимает `action`:

| Действие | Параметры |
| --- | --- |
| `displays` | Список `display_id` и размеров |
| `screenshot` | Необязательный `display_id`; по умолчанию последний или основной экран |
| `click`, `double_click`, `move` | `screenshot_id`, `x`, `y`; необязательный `button` |
| `drag` | `screenshot_id`, `x`, `y`, `to_x`, `to_y`, необязательный `button` |
| `scroll` | `screenshot_id`, `x`, `y`, `amount`: −20…20, положительное — вниз |
| `type` | `screenshot_id`, `text`: до 10 000 символов |
| `key` | `screenshot_id`, `keys`: до 6 имён, например `["CMD", "A"]` |
| `wait` | `duration_ms`: 1…2000; возвращает новый снимок |

Координаты считаются от левого верхнего угла полученного PNG, длинная сторона
которого ограничена 1600 пикселями. Они преобразуются в координаты выбранного
монитора с учётом масштаба и смещения, включая отрицательные координаты мониторов.
Для ввода обязателен последний `screenshot_id`, не старше 30 секунд. Он расходуется
до операции; после каждого ввода возвращается новое изображение. Изменение
конфигурации экранов требует нового снимка. Повторный JSON-RPC id отклоняется.
После неопределённого исхода операции агент должен сначала изучить новый снимок.

Инструмент `application` принимает `action`:

| Действие | Параметры / результат |
| --- | --- |
| `windows` | Имена приложений, заголовки и непрозрачные `window_id`; неоднозначные окна исключаются |
| `inspect` | `window_id`; дерево с `element_id`, `actions` и новым `snapshot_id` |
| `screenshot` | `window_id`; PNG только выбранного окна, до 1600 пикселей по длинной стороне |
| `invoke`, `increment`, `decrement` | `window_id`, `snapshot_id`, `element_id` |
| `set_value` | Те же ID и `text` до 10 000 символов; заменяет значение поля |

Ввод разрешён только для действия, объявленного элементом при последнем `inspect`.
Snapshot живёт 30 секунд, расходуется **до** вызова AX/UIA, в том числе при таймауте.
После успешного ввода возвращается новое дерево. Снимок не разрешает координатный
ввод и сбрасывает старый snapshot. После неизвестного исхода сначала проверьте окно,
не повторяйте действие вслепую. Неподдерживаемые действия завершаются явной ошибкой.

Протокол основан на [MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)
и [MCP-конфигурации Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Проверка

```sh
./gradlew :feature:session:impl:jvmTest --tests '*ComputerUse*Test' --tests '*ApplicationUseTest' --tests '*NativeApplicationDesktopTest' -Pmagicpaper.codingTools.offline=true --console=plain
./gradlew :feature:settings:impl:jvmTest --tests '*AutomationSettingsRenderTest' :app:jvmTest --tests '*AutomationPolicyTest' --tests '*ChatInputQueueTest' --tests '*SessionInputQueueTest' -Pmagicpaper.codingTools.offline=true --console=plain
```

Проверяются независимые scopes, generation/replay, истечение/расход snapshot,
отмена заблокированной записи, unknown outcome, импорт/ошибка сохранения, восстановленные
очереди, wrapping/semantics и доступность остановки. Используются искусственные
окна; тесты не читают рабочий стол и не двигают мышь. Native smoke проверяет запуск
bundled helper и отказ чужому window ID **без** системных запросов разрешений.
Он не доказывает работу AX/UIA на реальном окне.

Дополнительно задайте `MAGICPAPER_COMPUTER_NODE` (путь к Node ≥ 22.19) и
`MAGICPAPER_COMPUTER_CODEX` (путь к Codex), чтобы включить проверки настоящего
расширения pi и MCP-клиента app-server без аккаунта и внешних запросов.
`MAGICPAPER_COMPUTER_PI` (путь к установленному `dist/bundle/cli.js`) дополнительно
проверяет полный цикл pi: вызов инструмента и передачу PNG тестовой vision-модели.
Codex проверяется при первом подключении и после продолжения сохранённой сессии.
Превью и ограничения проверки: [AUTOMATION-ACCEPTANCE.md](desktop-ui/AUTOMATION-ACCEPTANCE.md).

Для подготовленного интерактивного Mac добавлен отдельный opt-in сценарий:

```sh
./gradlew :feature:session:impl:jvmTest --tests '*ApplicationUseMacIntegrationTest' -Pmagicpaper.application.native=true -Pmagicpaper.codingTools.offline=true --console=plain
```

Он сначала проверяет существующие TCC grants через внутренний `permissions`-запрос
helper (не инструмент модели). Проверка не запрашивает разрешения. При недостающем
доступе явно включённый тест падает **до** чтения окон и ввода; при выключенном
opt-in — skipped. Helper остаётся в `feature/session/impl/build/application-use/native-acceptance/<sha256>/`
для стабильной TCC identity. Сам fixture и его данные временные, удаляются после теста.
Тест не активирует окна: красное целевое окно и синее перекрытие располагаются за
окнами пользователя. Проверяются AX-действия, Unicode, stale/replay, защищённое поле,
захват перекрытого окна, foreground/cursor/clipboard sequence. Во время короткого
сравнения глобальных метаданных не двигайте мышь и не переключайте приложения:
ручное изменение тоже будет замечено тестом. Проверка работы пользователя параллельно
остаётся отдельным ручным сценарием. Ни аккаунт, ни LLM для этого теста не нужны.

Для остальной нативной приёмки используйте временный проект/тестовую программу, не рабочие
документы: окно с кнопкой-счётчиком, текстовым полем и другим foreground-окном.
При выключенном `computer` и включённом `application` проверьте `windows → inspect →
set_value/invoke`, Unicode, закрытое другим окном содержимое PNG и неизменность
foreground app, позиции мыши, буфера обмена и ввода пользователя. Затем проверьте
закрытое/пересозданное окно, ручное изменение поля после inspect, неподдерживаемый
canvas, отказ разрешений, зависший provider и отзыв во время действия. При таймауте
счётчик не должен изменяться повторно без нового inspect. Перезапуск MagicPaper
не должен выдавать доступ очереди; новый явный запрос — может.
Отдельно проверьте `computer` на настоящем desktop (включая второй монитор).
Реальный ввод, TCC, Windows UIA и установленный пакет проверяются на целевой ОС.
