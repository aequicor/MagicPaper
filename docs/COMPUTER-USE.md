# Экран и управление компьютером

В desktop-кодинг-сессиях есть панель «Доступ к экрану». Перед отправкой запроса
нажмите «Включить…» и выберите просмотр либо экран с мышью и клавиатурой.
Кнопка «Снимок» показывает превью; нажатие на него открывает увеличенное изображение.
Модель должна поддерживать изображения и вызовы инструментов.

Доступ получает только выбранная сессия. Завершение запроса, остановка агента,
«Отключить», удаление сессии и закрытие приложения отзывают его. Настройка не
сохраняется и не наследуется этапами планирования. Одновременно экраном пользуется
одна сессия. Следующий запрос требует нового включения доступа.

## Возможности и платформы

- Codex через подписку ChatGPT: локальный MCP подключается при старте и продолжении
  coding-сессии. Другие права Codex, включая сетевую песочницу, сохраняются.
  Перед продолжением завершённая сессия выгружается из app-server, чтобы применить
  новый MCP endpoint: обычный resume уже загруженной сессии сохраняет старый клиент.
  История остаётся в rollout и восстанавливается при resume.
- pi: встроенное расширение регистрирует тот же инструмент для выбранного
  API-провайдера, включая Anthropic, OpenAI-совместимые серверы и Google.
- macOS, Windows и Linux X11: PNG, выбор монитора, движение и нажатия мыши,
  двойной клик, перетаскивание, вертикальная прокрутка, текст и сочетания клавиш.
- Wayland, Android и браузер: управления системным рабочим столом нет.
- Это снимки по запросу, а не непрерывное видео. Действия выполняются на настоящем
  рабочем столе пользователя; приложение не создаёт изолированный виртуальный экран.

На macOS нужны системные разрешения «Запись экрана» и, для ввода,
«Универсальный доступ». Приложение проверяет разрешения перед операциями и показывает,
где их включить. После разрешения записи экрана может потребоваться перезапуск.
При запуске из IDE разрешение может относиться к Java/IDE. Windows UAC и защищённые
экраны не поддерживаются; системные ограничения не обходятся.

Снимки включают видимые окна и передаются выбранной модели. MagicPaper держит
последнее превью в памяти и очищает при отключении. Отдельных файлов скриншотов
не создаёт; движки Codex/pi могут сохранять изображения в собственной истории
инструментов, а хранение на стороне провайдера определяется его настройками.
Ввод Unicode использует временную вставку через буфер обмена с восстановлением
прежнего содержимого. История буфера обмена ОС или другие менеджеры буфера могут
сохранить вставленный текст.

## Устройство

`ComputerUse` — общий порт и временное состояние UI. `DesktopComputerUse`
сериализует операции, проверяет владельца и поколение разрешения. `AwtComputerDesktop`
выполняет захват и ввод через Java Robot; на macOS JNA проверяет разрешения системы.
JVM-модуль `jdk.httpserver` включён в упакованный desktop runtime.

Каждый активный запрос получает MCP endpoint на `127.0.0.1` со случайным портом и
случайным 256-битным bearer token. HTTP-запросы из браузера (`Origin`) отклоняются,
размер входа ограничен 64 КиБ. Endpoint закрывается в `finally`; старое поколение
разрешения не получает доступ после повторного включения. Настройка Codex при
выключенном доступе явно отключает прежний endpoint. Расширение pi получает
адрес и токен через окружение, исходник расширения не содержит токенов.

Инструмент `computer` принимает `action`:

| Действие | Параметры |
| --- | --- |
| `displays` | Список `display_id` и размеров |
| `screenshot` | Необязательный `display_id`; по умолчанию последний или основной экран |
| `click`, `double_click`, `move` | `screenshot_id`, `x`, `y`; необязательный `button` |
| `drag` | `screenshot_id`, `x`, `y`, `to_x`, `to_y`, необязательный `button` |
| `scroll` | `screenshot_id`, `x`, `y`, `amount`: −20…20, положительное — вниз |
| `type` | `screenshot_id`, `text`: до 10 000 символов |
| `key` | `screenshot_id`, `keys`: до 6 имён, например `["CMD", "A"]` |
| `wait` | `duration_ms`: 1…2000; возвращает новый снимок |

Координаты считаются от левого верхнего угла полученного PNG, длинная сторона
которого ограничена 1600 пикселями. Они преобразуются в координаты выбранного
монитора с учётом масштаба и смещения, включая отрицательные координаты мониторов.
Для ввода обязателен последний `screenshot_id`, не старше 30 секунд. Он расходуется
до операции; после каждого ввода возвращается новое изображение. Изменение
конфигурации экранов требует нового снимка. Повторный JSON-RPC id отклоняется.
После неопределённого исхода операции агент должен сначала изучить новый снимок.

Протокол основан на [MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)
и [MCP-конфигурации Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Проверка

`./gradlew :shared:jvmTest --tests '*ComputerUse*Test'` проверяет запрет ввода без
доступа, разделение сессий, координаты, устаревшие снимки, остановку во время
операции, HTTP-аутентификацию, защиту от повторов и доступность кнопки остановки.
Используется искусственный экран; тесты не читают экран пользователя и не двигают мышь.

Дополнительно задайте `MAGICPAPER_COMPUTER_NODE` (путь к Node ≥ 22.19) и
`MAGICPAPER_COMPUTER_CODEX` (путь к Codex), чтобы включить проверки настоящего
расширения pi и MCP-клиента app-server без аккаунта и внешних запросов.
`MAGICPAPER_COMPUTER_PI` (путь к установленному `dist/bundle/cli.js`) дополнительно
проверяет полный цикл pi: вызов инструмента и передачу PNG тестовой vision-модели.
Codex проверяется при первом подключении и после продолжения сохранённой сессии.
Превью панели: `shared/build/reports/computer-use/panel-narrow.png`.

Для ручной проверки включите доступ в desktop-сессии с vision-моделью, попросите
описать тестовое окно, затем выполнить клик и ввести текст в пустой документ.
Проверьте «Отключить» во время работы, повторное включение для следующего запроса,
второй монитор и отказ системных разрешений. Реальный ввод нужно проверять
отдельно на каждой целевой ОС.
