## Закрытый набор данных

`StrictExperienceCatalog.kt` задаёт три типа задач: резюме, список шагов,
уточнение неполного запроса. Четыре возможных признака результата:
слишком длинный ответ, пропущенный шаг, неверный формат, недостаток контекста.
API `record` принимает только перечисления, множество перечислений и boolean.
В панели нет редактора исходных фрагментов, инструкций, ID, версии или проверочных запросов.
Свободная строка локального поиска не сохраняется и не передаётся модели.

Журнал `~/.MagicPaper/skill-experience/experience.json` имеет `schemaVersion: 2`.
Хранятся случайный UUID, время, перечисления, boolean, связи кандидатов с UUID,
идентификатор шаблона, версия синтетического набора, числовые оценки и checksum baseline.
Схема отклоняет неизвестные поля/значения перечислений. Идентификаторы, контрольные
суммы, индексы и оценки проверяются при открытии. Нет исходных сообщений, имён
проектов, файлов, URL, свободных метаданных, сырых ответов модели или embedding-индекса.

Поиск сканирует живые записи. Повтором считаются ≥ 2 результата одного типа;
для генерации нужен хотя бы один успешный. Выбор ограничен 2–6 результатами.
Хранение по умолчанию 30 дней, настройка 1–365; максимум по 200 результатов/кандидатов.
Очистка проверяется при операциях, перед применением пакетов и каждые 60 секунд
работы приложения. После простоя выполняется при следующем запуске/обращении.

## Предпросмотр, генерация и проверки

1. Пользователь выбирает результаты и разрешённый текстовый API-профиль.
   Подписочный инструментальный транспорт исключён. Предпросмотр показывает
   точные сообщения выбора шаблона, провайдера/модель, обе допустимые инструкции,
   все синтетические сценарии/эталоны и формат проверочного запроса.
2. После отдельного разрешения выполняется 1 вызов выбора шаблона и 14 проверок.
   Первый ответ принимается только при точном равенстве `CONCISE` либо `STRUCTURED`.
   Пробелы, JSON, пояснения, произвольные инструкции и неизвестные значения отклоняются.
   Кандидат всегда собирается приложением из канонического текста и манифеста;
   LLM не пишет содержимое пакета. ID формируется из типа задачи, версии — `1.0.N`.
   Новые шаблоны не добавляют разрешений и зависимостей.
3. Для сравнения разрешена только активная версия, чей текст и **весь манифест**
   совпадают с каноническим шаблоном. Проверенный хеш и ручной review произвольного
   пакета недостаточны. В запросы идёт текст из каталога приложения, а не скопированный
   текст baseline. Если канонической активной версии нет, baseline — пустая инструкция.
4. На каждый тип задачи есть семь публичных синтетических запросов: 4 фиксированных,
   3 отложенных. Генератор получает только фиксированные. Активная версия и кандидат
   выполняют те же запросы через один фиксированный профиль. Метрика каждого запроса —
   точное совпадение с эталоном (0/1). Все семь результатов кандидата должны быть 1
   и не ниже результатов baseline. Ответ проверочной LLM не сохраняется, не показывается
   как отчёт и не включается в последующие запросы: сохраняются только оценки.
5. Полный контекст каждого вызова ограничен 24 000 символами, весь цикл — 60 секундами.
   Превышение, ошибка и отмена не активируют версию. Предпросмотр одноразовый;
   согласие привязано к точным сообщениям и снимку профиля. До каждого вызова остаётся
   дополнительная проверка известных ключей/сигнатур, но гарантия отсутствия переноса
   исходных секретов теперь обеспечивается закрытым потоком данных, а не детектором.
6. Кандидат автоматически сохраняется в карантин и проверяется. Панель опыта показывает
   «активная → кандидат»; панель пакетов — инструкцию, diff, происхождение, лицензию,
   разрешения и review. Успешные метрики сами по себе не устанавливают доверие и не
   активируют пакет. Изменение baseline блокирует продвижение даже со свежим согласием.

Это ограниченное улучшение шаблонов на синтетических проверках, а не доказательство
семантического качества на произвольных реальных задачах. Для расширения набора
нужно изменение проверенного каталога приложения; свободный текст не является обходом.

## Секреты, старые данные и удаление

Неизвестная секретная фраза не может быть значением типизированного наблюдения.
Произвольный ответ генератора отклоняется целиком; произвольный ответ проверяющей
модели может дать только неуспешную оценку. Имена, описания и инструкции стороннего
baseline не проходят проверку канонического пакета. UUID записей, временные метки,
ключи и адреса профиля не включаются в текстовые сообщения обучения.
Ключ подключения нужен выбранному транспорту для авторизации; он не является
содержимым обучающей памяти или LLM-сообщений.

«Память» здесь означает журнал, пакеты кандидатов, проверки и производные данные.
Это не обещание стирания JVM heap: транспорт неизбежно принимает ответ во временный
буфер, а подключение использует авторизационные данные. Исходные чаты и файлы
не читаются обучением; их существование в другом разделе приложения не изменяется.
Локальный JSON не шифруется; физическое стирание SSD не заявляется.

Прежний журнал без schemaVersion 2 **не переносится**: операции обучения, поиск
старых записей и применение пакетов блокируются. В панели доступно явное
«Удалить весь опыт» с подтверждением. Оно удаляет прежний текстовый журнал и
связанные версии, включая внутренние повреждённые копии, созданные восстановлением.
До успешного удаления старый файл остаётся для повтора операции после сбоя;
его текст и старые произвольные ID не копируются даже в очередь удаления нового журнала.
Старые данные до подтверждения сохраняются на диске, но не используются строгим обучением.

Для строгого журнала удаление инвалидирует предпросмотры, отменяет связанные работы,
записывает очередь удаления и очищает результаты, версии, review и ссылки отката.
После сбоя очистка заканчивается до следующего применения. Даже ответ LLM,
игнорирующий отмену, не восстанавливает удалённые записи: перед commit проверяются
отмена и поколение журнала. Поискового индекса нет. Удаление не активирует другую
версию автоматически. Экспорты пользователя и уже переданные провайдеру данные
остаются вне области локального удаления. Импорта/экспорта строгого журнала нет.

## Активация, разрешения и откат

Сохраняется существующая атомарная активация точного checksum после review и
подтверждения diff. Любые новые разрешения требуют отдельного согласия;
строгие шаблоны сами разрешений не запрашивают. Откат восстанавливает предыдущую
версию и её разрешения через существующий контракт, а не через запись флага enabled.

`rollbackRestoresExactInstructionAndDifferentNonEmptyPermissionsAcrossRestarts`
проверяет v1 с READ_PROJECT → v2 с NETWORK → v1 с READ_PROJECT.
Без отдельного согласия на возвращаемое разрешение откат отклоняется, байты snapshot
не меняются. После согласия и следующего открытия проверяется точное равенство
исходного SkillInstruction: версия, текст, checksum, метаданные и набор разрешений;
NETWORK отсутствует. Проверки карантина и запрета продвижения при регрессии сохранены.
