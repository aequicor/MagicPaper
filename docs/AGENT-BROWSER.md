# Браузер агента

Desktop-запуски Codex и Pi получают инструменты `magicpaper_browser_*` через
существующий `AgentToolBridge`. Настройка Google API или ключа поиска не нужна.
`browser.search` открывает `https://www.google.com/search?q=…` в Chromium.
CAPTCHA, вход и согласие на cookies остаются обычными страницами браузера.
Агент должен сообщать об этих состояниях, а не считать их поисковыми результатами.

| Инструмент | Назначение |
| --- | --- |
| `browser.open` | Открыть HTTP(S)-адрес, в том числе сервер проекта на localhost; вернуть `tabId` |
| `browser.search` | Открыть поиск Google в новой или существующей вкладке |
| `browser.snapshot` | URL, заголовок, дерево доступности, DOM, ошибки JavaScript и список вкладок |
| `browser.click`, `browser.fill`, `browser.press` | Взаимодействовать с элементами через селекторы Playwright |
| `browser.evaluate` | Проверить DOM, вычисленные стили и поведение JavaScript |
| `browser.screenshot` | Получить PNG видимой области в ответе инструмента, с заданным размером окна |
| `browser.validate_html` | Проверить HTML локальным Nu Html Checker; ошибки содержат строку и столбец |

Для HTML-проверки укажите ровно одно: `html` с текстом или `tabId`.
По умолчанию `source=RESPONSE` проверяет исходный ответ сервера. `source=DOM`
проверяет уже построенную браузером разметку: HTML-парсер может исправить исходные
ошибки, поэтому успешная DOM-проверка не доказывает корректность исходника.
Проверка разметки не устанавливает визуальную корректность: нужны снимок,
проверка нужных элементов и ошибок JavaScript. Длинные результаты ограничиваются
с явным признаком `truncated`; валидатор сохраняет общее число ошибок.

Локальные страницы открываются через HTTP-сервер проекта, запущенный штатным
терминальным инструментом. `file:`, `javascript:`, `data:` и адреса с учётными
данными не принимаются инструментом открытия. Браузер не подключается к личному
профилю пользователя; cookies и хранилища принадлежат отдельному контексту запуска.
Загрузки файлов отключены. Контекст и процесс закрываются вместе с мостом, а не
при навигации пользователя по экранам приложения. Следующий запуск получает
новые вкладки и профиль. Восстановление истории не запускает браузер автоматически.

Playwright запускает Chromium без видимого окна. Изображения доступны агенту через
MCP image blocks (Pi получает те же блоки). При первом открытии Playwright может
загрузить управляемые браузеры в свой стандартный кеш; нужен доступ к сети и место
на диске. Обычный startup приложения загрузок не делает. Для предварительной
установки Chromium и воспроизводимой локальной проверки:

```sh
./gradlew :feature:session:impl:installAgentBrowser
./gradlew :feature:session:impl:jvmTest -Pmagicpaper.browser.native=true --tests '*BrowserToolsTest' --tests '*HtmlValidationTest' --tests '*BrowserNativeTest' --tests '*AgentToolBridgeTest' --tests '*CodingSystemPromptsTest'
```

Нативная проверка использует локальный HTTP fixture и настоящий Chromium, без
LLM, аккаунтов или внешнего поиска. Установка браузера не является доказательством
доступности Google в сети пользователя. macOS, Windows и Linux поддерживаются
Playwright; проверку на каждой целевой ОС следует выполнять отдельно.

## Владение и ошибки

Владелец реализации — `feature/session/impl`, пакет `data.browser` в `jvmMain`.
`BrowserToolSession` — адаптер Playwright и владелец потока: создание, команды и
закрытие выполняются последовательно на одном потоке, как требует Playwright.
Вычисление JavaScript использует CDP через Playwright: обычный `Page.evaluate`
не имеет таймаута, поэтому deadline Chromium ограничивает синхронные циклы,
а таймер ограничивает ожидание Promise. Лимит — 15 секунд.
`ToolRegistry.attach` подключает команды только на время одного моста. Поэтому
они сохраняют общий `ToolExecutor`, проверки полномочий, события и receipts с
защитой от повторного эффекта. Отдельного глобального каталога или сервиса нет.
Вспомогательные verifier-запуски не получают браузерные команды.

Отказ до действия возвращается как явная ошибка с возможностью исправления.
Неподтверждённый внешний эффект проходит существующий механизм UNKNOWN, без
автоматического повтора. Диагностика браузера не пишет URL, введённый текст,
скрипты и содержимое страниц в обычные логи. Страницы и HTML-ошибки — недоверенные
данные. Скриншоты, DOM и результаты сохраняются в истории вызовов текущей сессии.

## UI-рекомендации

В общие инструкции обоих движков включена
[подборка awesome-ui-guides](https://github.com/willyp713/awesome-ui-guides).
При UI-задаче агент выбирает релевантный раздел и читает первоисточник через
браузер. Подборка дополняет правила проекта и дизайн-систему; не переопределяет их
и не заменяет проверку реализованного интерфейса.
