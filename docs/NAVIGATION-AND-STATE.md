# Навигация, runtime и постоянное состояние

Границы кода описаны в [MODULES.md](MODULES.md), результаты сборок и сравнение
с исходным набором тестов — в [MODULE-MIGRATION-VERIFICATION.md](MODULE-MIGRATION-VERIFICATION.md).
Версии закреплены в version catalog: [Decompose 3.5.0](https://github.com/arkivanov/Decompose/releases/tag/3.5.0)
и [Koin 4.2.2](https://github.com/InsertKoinIO/koin/releases/tag/4.2.2).

## Владение

Корень, Koin composition и навигация находятся в `:app` (`app/src`). Только
`desktopApp`, `androidApp` и `webApp` зависят от этого модуля. Перенос из прежнего
`shared` не меняет Kotlin-пакеты, сериализованные IDs, пути истории и ключи хранения.

Host создаёт `MagicPaperRuntime` и `ComponentContext` вне рекомпозиции.
Один изолированный `koinApplication` содержит репозитории, HTTP-клиенты,
сервисы фич и кодинг-рантайм. Фабрики компонентов получают зависимости через
конструкторы. Компонент владеет чтением выбранного экрана, подписками и выбором
файлов; исполнение, черновики сущностей и таймеры принадлежат сервисам приложения.

`MagicPaperRuntime.start()` сначала загружает настройки и выполняет миграции
ключей, затем связывает сервисы, восстанавливает работу и разрешает UI.
Повторный `start()` не повторяет восстановление. `close()` завершает всех уже
созданных владельцев и закрывает Koin даже после частичной ошибки запуска.
Он не подменяет пользовательскую команду остановки задания: сохранённые checkpoint
и неизвестный результат нативного процесса остаются предметом восстановления.

При сбросе корень временно переходит на нейтральный экран, владельцы прекращают
старые записи, хранилища очищаются, и те же сервисы начинают работу с новым
состоянием. Поколения записей запрещают поздним autosave возвращать удалённые
черновики. Долговечный reset epoch также блокирует старые записи из других вкладок.
Android сохраняет корень и runtime через `retainedComponent`,
Desktop получает файловую блокировку до DI.

## Адреса и журнал

Публичный `RootComponent` принимает `navigate`, `back`, `forward`,
`handleDeepLink`. Единственный координатор последовательно применяет команды
к `NavigationJournal(visits, cursor)`. Каждый `Visit` имеет собственный ID;
Decompose `ChildStack` представляет только префикс до курсора. Автоматическое
изменение стека через Back отключено.

- A → B → A содержит три посещения; повтор текущего маршрута не добавляет запись.
- Back/Forward меняют курсор. Новый переход после Back удаляет старую ветку Forward.
- Кнопка Back сначала закрывает `ChildSlot`; браузерный переход закрывает диалог
  и меняет курсор. Отложенное закрытие проверяет ID диалога.
- Paper-модальные компоненты регистрируются через `PaperDialogLifecycle`;
  дизайн-система не зависит от Decompose. Прямые Compose `Dialog`/`Popup` за её
  пределами запрещены проверкой Paper API.
- Sidebar выбирает сессию немедленно. Скрытие панели сохраняет сам экран.

| Раздел | Путь |
| --- | --- |
| Чаты | `/chat`, `/chat/{sessionId}` |
| Проекты | `/projects`, `/projects/{projectId}`, `/projects/{projectId}/sessions/{sessionId}` |
| Документация | `/docs`, `/docs/{articleId}` |
| Плагины и навыки | `/plugins`, `/plugins/{pluginId}` |
| Настройки | `/settings`, `/settings/models`, `/settings/engines`, `/settings/profiles/{profileId}` |

Нативный эквивалент: `magicpaper://` и те же сегменты, например
`magicpaper://projects/project-id/sessions/session-id`. Ссылка восстанавливает
журнал и затем добавляет переход. До завершения onboarding она ожидает в журнале.
Переход не создаёт объект, не отправляет запрос и не подтверждает анкету.
Несуществующий объект, включая сессию из другого проекта, показывает «не найден».
Отключённый плагин открывает действие явного включения.

## Черновики и секреты

`NavigationSnapshotStore` атомарно сохраняет полный журнал с курсором и ссылками
на отдельные записи состояния просмотра. `ReferencedNavigationSnapshotStore`
восстанавливает эти записи по ID посещения для корневых компонентов. Неизменяемые
записи состояния сохраняются до журнала; очистка после commit учитывает ссылки
всех вкладок. Старые inline-снимки читаются без перезаписи и мигрируют при следующем
успешном сохранении. `VisitPresentationState` сохраняет разрешённые значения Compose
`rememberSaveable`: прокрутку, раскрытие дерева, выбранные вкладки и параметры
панелей. Неизвестная или повреждённая форма снимка показывает ошибку и не
перезаписывает исходные данные пустым состоянием.

Редактируемые данные находятся в `DraftRepository` по ID сущности. Повторные
посещения чата/формы используют один черновик. `DraftSession` сначала восстанавливает
сырой ввод и затем упорядочивает записи по версиям. Это относится к сообщениям,
невалидным числовым полям, профилям, настройкам, планированию и ответам анкет,
созданию/переименованию сессии и редактированию будущих сообщений. Нативные формы
импорта, проверки, активации и отката навыков сохраняются отдельно по сущности;
согласия связаны с checksum и поколением. Формы локального опыта сохраняют
сценарий, признаки, невалидный срок хранения, выбранные результаты и ID профиля.
Сохранённый предпросмотр содержит описание; отправка требует нового действующего
предпросмотра и явного действия. Анкеты дополнительно связывают ответ с
ID и поколением запроса. Восстановленные согласия требуют явного подтверждения.
Редактирование будущего сообщения сохраняет ID команды в черновике. Принятие
фиксируется после долговечной записи входа до построения истории; повторная
попытка с тем же ID проверяет существующую запись, включая перезапуск приложения.

Вложения принадлежат приложению: `DraftBlobStore` хранит байты, обычная запись
черновика — ссылки. Запись байтов и ссылок упорядочена с удалением. Сборка мусора
удаляет файл только после исчезновения последней ссылки; повреждение записей
останавливает удаление. Tombstone позволяет повторить прерванную очистку.
Ошибка удаления временных данных после принятого сообщения оставляет черновик
очищенным и доступна для повторной попытки. Метаданные очистки сокращаются после
успешного удаления.

Черновик удаляется после успешной отправки/сохранения либо явной отмены.
Успех старой отправки очищает только захваченную версию и сохраняет более новый
ввод. Восстановление само по себе не выполняет действие. Удаление сущности очищает
и не открывавшиеся в текущем процессе черновики, отзывая старых писателей.

По выбранному требованию `SecretStore` хранит значения **без шифрования и
мастер-пароля**, отдельно от обычных записей. Desktop использует
`~/.MagicPaper/persistence`, Android — `filesDir/persistence`, Web — отдельные
object stores базы IndexedDB `magicpaper-persistence`. Это не меняет прежние
пути истории и сериализованные идентичности.

Миграция API-ключей профилей/поиска/legacy-настроек сначала записывает и проверяет
секрет, затем удаляет его из обычной записи. Повтор после прерывания безопасен.
Секретные поля форм/анкет проходят через тот же backend; их значений нет в
универсальных снимках просмотра. Встроенный Codex использует единственный штатный
`auth.json`, владельцем записи остаётся app-server. Временные subscription-токены
и внешние конфигурации движков не мигрируются.

Конфигурация Pi содержит литерал `$MAGICPAPER_LLM_API_KEY`; значение передаётся
в окружении дочернего процесса. Старые принадлежащие приложению копии очищаются
после reconciliation. Явный экспорт профиля сохраняет прежнюю семантику ключей;
черновики, журналы навигации и subscription-токены не экспортируются.

## Ошибки и диагностика

`core:logging` предоставляет `AppLog` с уровнями ERROR → INFO → DEBUG → TRACE;
по умолчанию включён INFO. Нормальные события содержат разрешённые метаданные
и непрозрачные ID, причины ошибок — только имена классов. Текст исключений,
запросы и ответы не выводятся. TRACE включается явно, создаётся лениво,
скрывает секреты и ограничивает размер; история имеет предел хранения.

Владелец операции связывает диагностическое событие с безопасной ошибкой UI.
Ошибка создания компонента не останавливает журнал: частичный компонент
уничтожается, а явная повторная попытка получает новый дочерний контекст.
Ошибки завершения runtime не мешают остальной очистке и доступны через
`shutdownErrors`.

## Hosts и проверка

Web использует `BrowserHistoryBridge` и собственный журнал, без параллельного
`withWebHistory`. Browser entries содержат ID журнала, сегмента и посещения.
Forward-ветка остаётся в постоянном хранилище даже после перезапуска.
Web Lock удерживает журнал за документом: дублированная вкладка получает новую
копию, а перезагрузка освобождённой вкладки сохраняет её прежний ID. Новая вкладка
восстанавливает независимую копию последнего журнала.
Порядок browser popstate и программных переходов проверяется через отдельный
`BrowserHistoryPort`; IndexedDB и настоящий browser history требуют также
браузерных тестов. Различие с библиотечным восстановлением описано в
[Decompose Web Navigation](https://arkivanov.github.io/Decompose/navigation/web-navigation/).

Совместимость сохранённых версий Kotlin/Compose для JS описана в
[WEB_ABI.md](WEB_ABI.md). Линковка JS и Wasm выполняется отдельно с ошибкой при
partial linkage. Публикация прямых URL требует fallback на `index.html` и загрузки
ресурсов от корня приложения.

Регистрация схемы и проверка установленных DMG/MSI/DEB описаны в
[desktopApp/packaging/README.md](../desktopApp/packaging/README.md).
Сборка пакета и unit-тест локального канала не заменяют проверку установленного
приложения на соответствующей ОС. Live-интеграции движков остаются opt-in.
