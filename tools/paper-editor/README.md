# Paper · Mission Visualization

Отдельный desktop JVM редактор макетов с настоящими Compose-компонентами Paper.
Каталог и интерактивный предпросмотр используют одни фикстуры из `:tools:paper-plugin`.
Обычная сборка MagicPaper не включает редактор и не требует субмодуля.

## Создание макета из чата MagicPaper

В desktop-сборке с редактором выберите проект в «Проекты и код» (единственный
проект выбирается автоматически), перейдите в обычный чат и напишите, например:
«Создай макет экрана входа». Используется выбранная модель чата.

MagicPaper открывает Paper Editor с папкой
`<проект>/design/layouts/chat-<ID диалога>`, передаёт модели каталог Paper и текущий
макет, проверяет её результат настоящим компилятором и рендерером. Некорректный
документ возвращается модели на исправление, максимум три попытки. Успешный результат
сохраняется в `screen.layout.md`, обновляется в редакторе и возвращается в чат как PNG.
Напишите «Добавь кнопку слева», чтобы продолжить в том же диалоге. Привязка проекта
сохраняется с чатом; переключение проекта не перенаправляет последующие правки.

Восстановление чата не запускает редактор. Если файл изменился вручную во время
генерации, агент сообщает о конфликте и предлагает повторить запрос с новой версии.
Предыдущая версия остаётся в `screen.before-agent.bak`. Отмена останавливает текущую
проверку; уже открытый редактор остаётся самостоятельным окном.

Это сценарий обычного чата, а не терминальная команда пользователя и не загрузка
Paper в пользовательский реестр плагинов. Чаты кодинг-сессий Pi/Codex этим маршрутом
не перехватываются. На Android/Web возвращается сообщение о доступности desktop.
Проверяется компиляция и реальный рендер; автоматическая оценка изображения моделью
или сравнение с эталонной картинкой не выполняются.

Для поставки MagicPaper с редактором:

```sh
./gradlew -PpaperEditor=true :desktopApp:createDistributable
```

Редактор включается в ресурсы приложения. В dev checkout адаптер также находит
локальную сборку `tools/paper-editor/build/compose/binaries/main/app`. Для отдельной
установки можно явно задать путь до исполняемого файла через
`MAGICPAPER_PAPER_EDITOR` или JVM property `magicpaper.paperEditor.executable`.
Обычная сборка без флага остаётся доступной; в ней отсутствие инструмента сообщается
в чате, без предложения модели выдать вымышленный результат.

## Запуск

Следующая команда нужна для самостоятельного ручного запуска редактора разработчиком:

```sh
git submodule update --init --recursive
./gradlew -PpaperEditor=true :tools:paper-editor:run
```

Нужны обычное окружение сборки MagicPaper и JDK 21. Флаг включает два JVM-модуля
и отдельную composite build Mission Visualization. Kotlin/AGP внешнего проекта
остаются его собственными; модули редактора не включаются напрямую в MagicPaper.
Без субмодуля флаг выдаёт команду инициализации. Версию инструмента фиксирует gitlink.

Для macOS приложения: `./gradlew -PpaperEditor=true :tools:paper-editor:createDistributable`.
Результат: `build/compose/binaries/main/app/PaperEditor.app` в этом модуле.
Настройки редактора находятся в `~/.magicpaper/paper-editor`; для изолированного запуска
добавьте `-PpaperEditorDataDir=/absolute/path`.

## Верстка и сверка

1. Откройте проект — папку с `.layout.md`. Для первого знакомства скопируйте
   [пример](examples/paper-workspace.layout.md) в отдельную папку и откройте её.
2. Слева в Components найдите Paper-компонент. Выберите Frame на холсте и нажмите
   компонент каталога: Instance вставится в выбранный Frame. Без выбранного Frame
   используется корневой Frame страницы. В закрытый для редактирования слой вставка запрещена.
3. Перемещайте и меняйте размер на холсте. В Properties → Component измените текст,
   выбор, прогресс, состояние или вариант; текстовые изменения применяются кнопкой Apply.
   Layout открывает штатную геометрию редактора. Undo/Redo и сохранение работают через
   те же команды, что и для остальных объектов.
4. В Interactive preview вводите текст, нажимайте кнопки, переключайте выбор,
   открывайте меню и диалоги. Это демонстрационное состояние, оно не записывается в макет.
   Параметры слотов составных компонентов представлены фиксированными примерами;
   для произвольной композиции используйте Frame/AutoLayout и отдельные Instance.
5. Сверяйте холст с живым предпросмотром, отдельно выбирая macOS/Windows и масштаб
   текста 100/150/200%. В узком окне Components и Properties открываются вкладками,
   Canvas сохраняет всю ширину. Windows-профиль показывает Paper-метрики, но не
   заменяет запуск на реальной Windows.

Canvas получает растровые изображения из изолированных Compose-сцен. Масштаб холста
не входит в ключ рендера: zoom/pan используют существующие преобразования Canvas.
Ключ содержит ID, свойства, варианты (в том числе состояние, платформу и масштаб
текста) и размер. Кеш проекта ограничен 64 MiB/96 изображениями, одно изображение —
4096 px на сторону и 4 MP. Сцена закрывается после снимка, изображения — при вытеснении
или закрытии проекта. Анимация на холсте представляет фиксированный кадр; движение
проверяется в Interactive preview.

При изменении параметров прежнее изображение не выдаётся за актуальное: до нового
рендера показывается placeholder. Ошибка выбранного компонента видна в инспекторе
с Retry. Неизвестные библиотеки/компоненты и несовместимые свойства диагностируются;
исходные Instance, libraryRef, componentId, props и variant сохраняются.
Расширения не имеют зависимостей на сервисы приложения, пользовательский реестр
плагинов, сеть или сохранение пользовательских данных из callbacks.

## Проверки

```sh
./gradlew -PpaperEditor=true :tools:paper-plugin:test :designSystem:jvmTest \
  :mission-visualization:engine:ir:jvmTest :mission-visualization:engine:frontend:jvmTest \
  :mission-visualization:engine:backend-compose:jvmTest :mission-visualization:shared:jvmTest \
  :tools:paper-editor:createDistributable
python3 docs/verify-module-architecture.py --self-test
python3 docs/desktop-ui/verify-design-system.py --self-test
python3 docs/desktop-ui/verify-map.py --self-test
```

Рендеры: `tools/paper-plugin/build/reports/paper-plugin/`; JUnit-отчёты лежат в обычных
`build/reports/tests` соответствующих владельцев. [Покрытие каталога](../paper-plugin/COVERAGE.md),
[приёмка](ACCEPTANCE.md), [общий API расширения](../mission-visualization/docs/design-system-plugins.md).
Именованные Preview находятся в `PaperPreviews.kt`, группа `Paper plugin`.

Автоматическое сравнение изображений, загрузка JAR-плагинов, генерация Kotlin и
встраивание редактора в MagicPaper не входят в эту версию.

## Обновление внешнего инструмента

Базовая ревизия: `4f0854953222eaf789d64e86e646201212b142af`.
Общие изменения редактора находятся в отдельном коммите ветки
`codex/paper-design-system-plugin` его remote. Сначала опубликуйте новый коммит в
Mission Visualization, затем обновляйте gitlink в MagicPaper и повторяйте проверки.
Не фиксируйте gitlink на коммит, доступный только локально.
