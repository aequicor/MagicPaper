# MagicPaper — «Шалость удалась» ✦

Минималистичный ИИ-агент в стилистике магической бумаги (вселенная Гарри Поттера):
мягкие пастельные тона, пергамент и чернила. Один экран, один диалог, одна цель — помочь.

## Возможности

- **ИИ-чат и несколько провайдеров**: подключайте несколько «магических источников»
  одновременно — любой OpenAI-совместимый сервер (Ollama, LM Studio, vLLM, OpenRouter,
  OpenAI), Anthropic (Claude) и Google Gemini. В desktop также доступен вход через
  ChatGPT для моделей OpenAI по подписке — без API-ключа, через официальный Codex
  app-server; Android и Web этот источник показывают отключённым. У каждого источника — своя модель,
  уровень усилия (дискретные уровни с привычными именами — `default / off / min / low / medium / high / xhigh / max / auto`,
  как в других агентах; ручка показывает только те уровни, которые принимает
  конкретная модель — по объявлению провайдера в его каталоге `/models`, иначе по curated-каталогу
  и семейству имени; провайдер мапит их в свой нативный формат) и тонкие настройки (температура, максимум
  токенов, таймаут, глубина истории, свой системный промпт).
  Усилие меняется и в чате (переключатель источника — там же выбор модели), и в настройках источника
  для его дефолтной модели; выбор запоминается за моделью, а не за источником.
  У источника можно отметить избранные модели — именно они показываются при выборе модели в чате и кодинг‑сессиях.
  Desktop-подписка ChatGPT работает и в обычном чате, и в проектных coding-сессиях;
  для coding используется workspace-write sandbox выбранного проекта.
  Переключение источника —
  отдельной кнопкой прямо в чате: выбор действует для текущего свитка или глобально.
  Без настройки агент честно сообщает, что источник не подключён.
- **Вложения**: кнопка со скрепкой в чате и кодинг-сессиях — изображения уходят модели напрямую (если она поддерживает зрение), текстовые файлы подмешиваются содержимым, до 8 файлов на сообщение. В кодинг-сессиях файлы раскладываются в изолированную папку рантайма, а агенту передаются пути к ним.
- **Встроенный поиск**: движки на выбор — Wikipedia (без ключей), Querit.ai,
  Google Programmable Search, режим AUTO (настроенный ключевой движок, иначе Wikipedia).
- **Встроенная документация**: справочник по приложению живёт в коде, доступен офлайн;
  агент использует его для ответов на вопросы о программе.
- **Плагины**: интерфейс расширяется плагинами (SPI `MagicPlugin` + реестр).
  В комплекте: Заметки, Фокус-таймер, Счёты, Лавка навыков, Самообучение.
  Включение/выключение на экране плагинов.
- **Магазин навыков**: встроенный каталог проверенных временем скиллов
  (резюме, вычитка, планы, сравнения…). Установка в один клик, политика
  конфликтов по имени, навыки автоматически подхватываются агентом.
- **Самообучение**: агент сам создаёт навыки из удачных диалогов — черновик
  формулируется моделью (или из запроса без модели), редактируется и
  сохраняется только после подтверждения пользователя.
- **Проекты и код (кодинг-агент)**: раздел для работы с проектами — рабочими
  папками. Кодинг-агент (по умолчанию пи-агент, десктоп) читает файлы проекта
  и выполняет запросы прямо в его директории, продолжая контекст между
  запусками (сессии). Кодинг-сессии живут в левом меню — списком под выбранным
  проектом, у каждой свой кружок активности, быстрый ответ и меню прогона.
  В диалоге сессии — чип с текущим источником, моделью и усилием: тап открывает
  переключатель, где для сессии выбираются свой источник (или основной), своя
  кодинг-модель и уровень усилия — отдельно от чата.
  Движок ставится автоматически при первом обращении —
  изолированно в папке данных приложения: системный Node ≥ 22.19 либо
  официальный дистрибутив Node в ту же папку; сам агент ставится через
  `npm --prefix` без скриптов установки. Никаких системных установок;
  кнопка «Удалить зависимости» и удаление приложения стирают всё.
- **Безопасность и изоляция**: данные живут в папке пользователя (десктоп) или
  localStorage (браузер), приложение не требует прав администратора,
  при удалении программы удаляются и все данные.
- **Переносимость профиля**: экспорт/импорт файла профиля — настройки, состояние
  плагинов и вся история чатов.

## Планирование проекта

Плагин «Планирование» хранит дерево решений: диалог уточнений, альтернативы на любом
уровне, относительные оценки, выбранный путь и зависимости. В интерактивном графе
можно менять будущие этапы и назначать каждому источник, модель и effort.

Desktop выполняет независимые этапы Git-проекта в отдельных worktree (по умолчанию
два одновременно), проверяет результаты и объединяет их. Проекты без Git выполняются
последовательно. Исходный Git index и HEAD сохраняются; новые пользовательские правки
проверяются перед переносом. Git-проект нужно открывать от корня репозитория.

После перезапуска ранее запущенный план продолжается автоматически. Явная пауза и
остановка сохраняются. Журнал различает выполнение, проверку, объединение и перенос:
подтверждённые операции повторно не применяются. При неизвестном результате команды,
неисправимой ошибке проверки или конфликте граф показывает требуемое действие.
Временные сетевые ошибки имеют ограниченные повторы; счётчики сохраняются.

Проверки восстановления и графа: `./gradlew :shared:jvmTest`. Изображения реального
Compose-графа генерируются тестом в `shared/build/reports/planning/`.
Архитектура, восстановление и сценарии проверки: [Планирование](docs/PLANNING.md).

## Платформы

- Десктоп (Windows / macOS / Linux): `:desktopApp`
- Веб (браузер): `:webApp` — Kotlin/JS и Kotlin/Wasm
- Android: `:androidApp`

## Запуск

```bash
./gradlew :desktopApp:run                      # десктоп
./gradlew :webApp:wasmJsBrowserDevelopmentRun  # веб (wasm)
./gradlew :webApp:jsBrowserDevelopmentRun      # веб (js)
./gradlew :androidApp:assembleDebug            # android
```

Тесты: `./gradlew :shared:jvmTest`
(интеграционный тест пи-агента с реальной установкой:
`./gradlew :shared:jvmTest --tests "*PiCodingRuntimeIntegrationTest" -Pmagicpaper.pi.it=true`)

## Типографика

Фирменный шрифтовой стек встроен через Compose Resources
(`shared/src/commonMain/composeResources/font/`) и одинаков на десктопе,
Android и в браузере:

- **Дисплейная** — *Cormorant Garamond* (бренд, крупные заголовки);
- **Текстовая** — *Literata* (чат, доки, подписи);
- **Моно** — *JetBrains Mono* (блоки кода).

Стек покрывает латиницу (вкл. расширенную), кириллицу (вкл. расширения),
греческий и вьетнамский; остальные письменности дорисовывает системный
фолбэк платформы. Все гарнитуры — SIL Open Font License 1.1, тексты лицензий
и атрибуция — в `font/OFL_ALL.txt`. План и обоснование — `docs/PLAN-typography-i18n.md`.

## Архитектура (Clean + SOLID)

```
shared/
  domain/    — ядро: модели, порты (интерфейсы), оркестратор агента,
               модели кодинг-агента (проекты, события протокола, порт рантайма).
               Ноль зависимостей от фреймворков.
  data/      — адаптеры портов: репозитории поверх хранилища, поисковые движки,
               LLM-шлюз (OpenAI-совместимый), встроенная документация,
               парсер протокола пи-агента, хранилище проектов.
  plugins/   — SPI плагинов и реестр; встроенные плагины.
  ui/        — Compose Multiplatform: тема «магической бумаги», экраны, ViewModel.
  di/        — корень композиции (ручная сборка графа — без тяжёлых фреймворков).
  jvmMain    — кодинг-рантайм пи-агента (изоляция зависимостей, процессы).
  webMain/jsMain/wasmJsMain/androidMain — платформенные актуалы.
```

Принципы: домен не знает о Ktor/Compose/файлах (DIP), экраны получают состояние
неизменяемым снапшотом, плагины подключаются без изменения ядра (OCP).

### Добавление плагина

1. Реализуйте `MagicPlugin` (id, title, description, icon, `Content()`).
2. Зарегистрируйте в `di/Dependencies.kt` (`registry.register(...)`).
Всё остальное (экран плагинов, переключатели, панели) работает автоматически.
