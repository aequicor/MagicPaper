## Цель работы

Превратить планирование в сохраняемое дерево решений проекта:
цель → уточнения → альтернативы и оценки → выбранный путь → зависимости →
источник/модель/effort → реализация. Планирование и редактирование доступны
в Desktop, Web и Android; выполнение и автоматическое восстановление — в Desktop.
Активные планы должны продолжаться после перезапуска приложения без открытия
панели; явно приостановленные и остановленные планы не возобновляются.

Сохранять существующие пользовательские изменения и интеграцию ChatGPT.
Подробное описание текущей архитектуры: `docs/PLANNING.md`. Старый документ
`docs/PLAN-coding-planning.md` помечен как исторический.

## Что реализовано

- Сохраняемые узлы дерева, вложенные альтернативы, оценки и приоритеты,
  назначения моделей, ревизии, намерение пользователя, фазы, попытки и журнал.
  Компилятор выбранного пути проверяет ссылки, циклы, неактивные зависимости,
  общие этапы и запрет изменения уже начатой работы. Старые планы мигрируют.
- `PlanComposer` получил уточнение, генерацию альтернатив и пересчёт участка
  через `DecisionPlanner`. Ответы проходят проверку и ограниченные исправления;
  сохраняются ручные назначения/выборы и незатронутые участки. Ответ можно
  применить поверх новых отчётов, но не поверх параллельных ручных изменений.
- Новый Compose-граф вместо линейной панели: масштаб, перемещение, раскрытие,
  выбор узла, клавиатура, показ целиком, адаптивное расположение диалога.
  Панель узла редактирует будущие этапы, зависимости и модель/effort.
  Служебные проверки и конфликты показываются через проекцию графа.
- `PlanningExecutionService` принадлежит приложению и запускается из DI.
  Планировщик готовых этапов поддерживает Git-параллельность 1–8 (по умолчанию 2),
  зависимости, последовательный режим без Git, паузу, остановку и восстановление.
- `GitPlanningWorkspace`: отдельный index начального снимка, изолированные
  worktree попыток и интеграции, стабильные ссылки коммитов, последовательное
  объединение, ограниченные исправления конфликтов и общая проверка.
  Перенос в исходную папку использует манифест и хеши до/после, сохраняет
  исходные HEAD/index и проверяет пользовательские правки.
- Надёжная запись файлов, резервный снимок, контрольные записи по проектам
  и записи удаления. Ошибка сохранения блокирует изменения и останавливает
  исполнителей до восстановления хранилища. Повреждённые планы не исчезают молча.
- Записанные фазы проверки/объединения/переноса позволяют продолжить операцию
  с нужной границы. Merge-коммит сам по себе не подтверждает прохождение проверки.
  Счётчики исправлений и сетевых повторов сохраняются; есть Retry-After и задержки.
- Модель и effort закрепляются за попыткой. Pi использует конфигурацию каждой
  сессии вместо общего изменяемого `models.json`. Добавлены проверки движка
  и авторизации Codex до запуска работ.
- Принадлежность процессов сверяется по PID, времени старта и владельцу.
  Windows Job Object завершает дочерние инструменты при закрытии владельца.
  Codex различает подтверждение завершения и потерю соединения; восстановление
  прерывает принадлежащий запуску turn, не завершая общий сервер других сессий.
- Живые отчёты пакетируются, поток периодически сохраняется даже при тишине
  движка. Из диагностик исключаются известные ключи и типовые секреты подключения.
- README, описание плагина и встроенная справка обновлены.

## Что осталось непроверенным на момент паузы

1. **Две последние правки ещё не прошли повторный прогон:**
   - планировщик учитывает `retryAt` и блокировку каждой попытки, даже если
     общая причина ожидания была заменена другой параллельной ошибкой;
     добавлен тест `savedRetryDeadlineIsRespectedEvenWithoutTheRunIssue`;
   - в графе зарезервировано 48 dp сверху под «Показать целиком», чтобы кнопка
     не закрывала заголовок первого этапа на узком экране. Нужно повторить
     Compose-тест и просмотреть изображения.
2. Дополнительный прогон настоящих движков был **прерван по просьбе пользователя**:

   ```powershell
   .\gradlew.bat :shared:jvmTest '-Pmagicpaper.codex.it=true' '-Pmagicpaper.pi.it=true' --console=plain
   ```

   Codex использует отдельный пустой профиль; Pi — локальный сервер модели
   и отдельную установку. Итоговый успех этого прогона не подтверждён.
   Последний локальный журнал: `build/planning-engine-integration.log`.
   Команда остановлена Ctrl+C; после остановки процессов Gradle Wrapper/Test
   Executor не обнаружено. Не считать эти интеграционные тесты пройденными.
3. Не выполнен полный сценарий аварийного завершения всего GUI-приложения
   с реальными удалёнными исполнителями на каждой границе операции. Имеются
   тесты инъекции сбоев и настоящих локальных дочерних процессов.
4. Нативная проверка аварийного завершения дочерних инструментов проведена
   на Windows. Для macOS/Linux нужно отдельно проверить оставшиеся процессы
   и восстановление; Windows Job Object на этих платформах не применяется.
5. Перед завершением всей задачи сверить реализацию с полной таблицей ошибок
   исходного плана во всех фазах, включая сетевые исключения, авторизацию,
   прерванные внешние команды и ограниченные повторы. Не обещать безопасный
   повтор, если результат внешнего действия нельзя установить.
